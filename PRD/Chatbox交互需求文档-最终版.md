# Chatbox 交互需求文档

| 文档属性 | 内容 |
|---|---|
| 文档状态 | 最终版 |
| 适用范围 | Agent 会话页 Chatbox 输入区域 |
| 语言范围 | 简体中文、英文 |
| 正文字符上限 | 20,000 个字符 |
| 单条消息附件上限 | 20 个顶层附件 |

## 1. 文档范围

本需求包含以下功能：

1. 文本输入与发送。
2. 上传附件。
3. 大文本粘贴并转换为 TXT 附件。
4. 复制、粘贴、撤销与还原。
5. 消息引用与回复。
6. 输入草稿自动保存。
7. 技能、MCP、店铺及工作流引用；文件通过附件入口添加。

以下内容不在本需求范围内：

1. Agent 思考、工具调用、上下文整理、异常重试、完成和中断等会话状态的定义。
2. Agent 内部思维链展示。
3. 附件发送后的解析和内容处理。
4. 技能、MCP、店铺和工作流的后台配置管理。

Agent 工作状态由单独的会话状态需求定义。本需求只规定 Chatbox 的对应表现：

- 当前允许发送新消息时，发送按钮可用。
- 当前不允许发送新消息时，发送按钮禁用，并说明不能发送的原因。

## 2. 通用规则

### 2.1 发送条件

同时满足以下条件时，发送按钮可用：

1. 正文、附件、消息引用或资源引用中至少存在一项有效内容。
2. 正文不超过 20,000 个字符。
3. 所有附件均处于“上传成功”状态。
4. 不存在校验失败、上传失败或已失效的附件。
5. 不存在失效或无权限的消息引用和资源引用。
6. 当前会话允许发送新消息。

任一条件不满足时，发送按钮禁用。

### 2.2 数据清理时机

1. 消息发送成功后，清空当前正文、附件、消息引用、资源引用及草稿。
2. 消息发送失败时，完整保留当前正文、附件、消息引用和资源引用。
3. 切换会话时保存当前会话草稿，并恢复目标会话草稿。

### 2.3 界面语言

1. 提示文案跟随用户当前选择的界面语言。
2. 中文界面展示中文，英文界面展示英文，不同时展示两种语言。
3. 涉及文件类型时，提示中必须展示具体的文件后缀。

## 3. 文本输入与发送

### 3.1 正文输入规则

1. 输入框支持普通文本、换行、中文输入法和 Markdown 原文。
2. 单条消息正文最多包含 20,000 个字符。
3. 一个换行、一个空格和一个制表符均计为一个字符。
4. 一个完整 Emoji 按一个用户可见字符计数。
5. 正文达到 18,000 个字符后，在输入框右下角显示字符计数，格式为 `18,000 / 20,000`。
6. 正文达到 20,000 个字符后，键盘输入不再写入正文。
7. 用户删除内容后，字符计数实时更新，并恢复输入能力。
8. 仅包含空格、换行或制表符的正文视为空正文。
9. 输入框最低显示 3 行，最高显示 10 行；超过 10 行后输入框内部纵向滚动。

### 3.2 键盘与发送交互

| 场景 | 处理规则 |
|---|---|
| 桌面端按 `Enter` | 发送消息 |
| 桌面端按 `Shift + Enter` | 插入换行 |
| 中文输入法处于选词状态时按 `Enter` | 确认选词，不发送消息 |
| 移动端按键盘换行键 | 插入换行 |
| 点击发送按钮 | 发送消息 |
| 发送按钮禁用 | 点击无响应，并保留当前输入内容 |

### 3.3 发送过程

1. 用户触发发送后，立即在会话区生成用户消息气泡。
2. 消息提交期间，消息气泡显示“发送中”。
3. 同一条消息提交期间禁止重复提交。
4. 消息成功提交后，状态变为“发送成功”。
5. 消息发送失败时，消息气泡显示失败状态和“重新发送”操作。
6. 重新发送时，不重复上传仍然有效的附件。
7. 用户可以在失败消息上选择“重新编辑”，将原内容恢复到 Chatbox 后修改并再次发送。

## 4. 上传附件

### 4.1 支持的上传方式

| 上传方式 | 规则 |
|---|---|
| 拖拽上传 | 支持将文件或文件夹拖拽到输入框区域 |
| 点击上传 | 点击“上传附件”后打开本地文件选择器 |
| 文件夹上传 | 点击“上传文件夹”后打开本地文件夹选择器 |
| 多选上传 | 文件选择器支持一次选择多个文件 |
| 剪贴板上传 | 粘贴文件、图片或截图时，按照附件上传处理 |
| 大文本上传 | 超过正文容量的大文本转换为 TXT 后，按照附件上传处理 |

### 4.2 文件类型白名单

文件扩展名匹配不区分大小写。只有以下类型允许上传：

| 分类 | 允许的扩展名或文件名 |
|---|---|
| 文本 | `txt`、`md`、`markdown`、`rst`、`pdf`、`doc`、`docx`、`docm`、`rtf`、`odt`、`epub`、`log`、`xmind`、`ppt`、`pptx`、`pptm`、`odp` |
| 表格与结构化数据 | `csv`、`tsv`、`xls`、`xlsx`、`xlsm`、`ods`、`json`、`jsonl`、`ndjson` |
| 图片 | `png`、`jpg`、`jpeg`、`jfif`、`webp`、`gif`、`svg`、`bmp`、`ico`、`tif`、`tiff`、`heic`、`heif`、`avif`、`apng`、`psd`、`raw`、`cr2` |
| 音频 | `mp3`、`wav`、`aac`、`flac`、`m4a`、`ogg`、`opus`、`weba` |
| 视频 | `mp4`、`mov`、`webm`、`mkv`、`m4v`、`ogv`、`avi`、`mpeg`、`mpg` |
| 压缩包 | `zip`、`7z`、`rar`、`tar`、`gz`、`tgz`、`bz2`、`xz` |
| 代码文件 | `js`、`mjs`、`cjs`、`jsx`、`ts`、`tsx`、`mts`、`cts`、`py`、`pyi`、`pyw`、`ipynb`、`java`、`go`、`rs`、`css`、`scss`、`sass`、`less`、`html`、`htm`、`xml`、`yaml`、`yml`、`toml`、`ini`、`env`、`sh`、`bash`、`zsh`、`fish`、`ksh`、`sql`、`c`、`cpp`、`cc`、`cxx`、`h`、`hpp`、`hh`、`cs`、`php`、`rb`、`swift`、`kt`、`kts`、`dart`、`vue`、`svelte`、`astro`、`scala`、`lua`、`r`、`jl`、`pl`、`pm`、`ps1`、`bat`、`cmd`、`gradle`、`lock`、`diff`、`patch`、`cmake`、`tf`、`hcl`、`proto`、`graphql`、`gql`、`properties`、`conf`、`cfg` |
| 无扩展名代码文件 | `Dockerfile`、`Makefile` |
| 安装包与二进制文件 | `exe`、`dmg`、`apk` |
| 文件夹 | 本地文件夹，内部文件必须逐个通过白名单校验 |

白名单校验规则：

1. 普通文件按最后一个扩展名判断类型。
2. `.env` 文件按 `env` 类型处理并允许上传。
3. 无扩展名文件仅允许文件名为 `Dockerfile` 或 `Makefile` 的文件上传。
4. 文件名匹配 `Dockerfile` 和 `Makefile` 时区分实际文件名，不要求扩展名。
5. 文件扩展名不在白名单内时，不得进入上传流程。
6. 通过白名单校验的文件仍需通过安全校验；安全校验失败时不得发送。

### 4.3 文件数量规则

1. 单条消息最多包含 20 个顶层附件。
2. 一个直接选择的文件计为一个顶层附件。
3. 一个直接选择的文件夹计为一个顶层附件，文件夹内部文件不单独占用 20 个附件名额。
4. 大文本转换生成的一个 TXT 文件计为一个顶层附件。
5. 达到 20 个顶层附件后，不允许继续添加。
6. 批量选择导致总数超过 20 个时，按照本次选择顺序，仅添加能够补足到 20 个的前 N 项。
7. 超出数量上限的剩余项目不创建附件卡片，并展示数量超限提示。
8. 校验失败的附件卡片占用一个附件名额，用户移除后释放名额。

### 4.4 文件大小规则

| 文件分类 | 单个附件大小上限 |
|---|---:|
| 图片 | 100 MB |
| 视频 | 1 GB |
| 压缩包 | 1 GB |
| 文件夹 | 文件夹内全部文件合计 1 GB |
| 其他文件 | 1 GB |

大小计算规则：

1. `1 KB = 1,024 bytes`。
2. `1 MB = 1,024 KB`。
3. `1 GB = 1,024 MB`。
4. 文件大小等于上限时允许上传，超过上限时禁止上传。
5. 单条消息不额外设置全部附件的合计大小上限。
6. 空文件允许上传，大小显示为 `0 KB`。

### 4.5 文件夹规则

1. 文件夹目录最大深度为 10 层。
2. 用户选择的根文件夹记为第 1 层。
3. 任一文件或子目录所在层级超过第 10 层时，整个文件夹校验失败。
4. 允许上传空文件和空目录。
5. 文件夹内每个非空文件必须通过文件类型、文件大小和安全校验。
6. 文件夹内任一文件校验失败时，整个文件夹标记为校验失败，不上传其中任何文件。
7. 文件夹总大小为内部全部文件大小之和，不能超过 1 GB。
8. 文件夹名称和内部相对目录结构必须完整保留。

### 4.6 重复上传规则

1. 相同文件或文件夹允许重复上传。
2. 每次添加均生成独立附件卡片，并占用一个附件名额。
3. 重复上传的附件保留原文件名，不做重命名或合并。
4. 系统不校验附件内容是否重复，也不展示重复上传提示。

### 4.7 上传状态

单个附件按照以下状态流转：

`本地校验中 → 等待上传 → 上传中 → 安全校验中 → 上传成功`

非标准图片在上传成功前增加“图片处理中”状态。

异常状态包括：

- 数量超限。
- 文件类型不支持。
- 文件大小超限。
- 文件夹层级超限。
- 文件夹内部文件校验失败。
- 上传失败。
- 安全校验失败。
- 图片格式转换失败。
- 视频封面提取失败。

其中：

1. 图片格式转换失败时阻止发送，直至用户移除该图片或重新上传成功。
2. 视频封面提取失败不阻止发送，降级为视频类型图标。
3. 其他异常状态均阻止消息发送，直至用户移除异常附件或重试成功。

### 4.8 批量上传规则

1. 批量上传时，每个顶层附件独立校验并独立上传。
2. 一个附件失败不终止其他附件上传。
3. 校验失败的附件保留在附件区，并以错误样式展示具体原因。
4. 出现两个及以上不同错误时，除卡片级错误外，再展示统一批量错误提示。
5. 批量上传过程中，用户可以单独取消、移除或重试任一附件。
6. 批量上传未全部结束前，消息发送按钮保持禁用。

### 4.9 附件区布局与排序

1. 附件区位于正文输入框上方。
2. 所有附件使用单行横向排列。
3. 超出可视宽度时，附件区支持横向滚动。
4. 附件区最多展示 20 个附件卡片。
5. 校验失败或上传失败的附件始终排在最前面，错误附件之间按错误发生时间正序排列。
6. 正在校验、等待上传和上传中的附件排在错误附件之后，按添加时间正序排列。
7. 上传成功的附件排在最后，按上传成功时间正序排列。
8. 附件状态变化后，根据上述规则实时重新排序。
9. 横向滚动位置不得因非当前可视附件的状态变化而自动跳回起点。

### 4.10 附件信息展示

| 展示项 | 规则 |
|---|---|
| 文件类型图标 | 按文本、表格、图片、音频、视频、压缩包、代码、安装包与二进制、文件夹、其他十类展示 |
| 文件名 | 展示文件名和完整后缀；空间不足时从名称中间省略，并保留名称首部、名称最后一个字符和完整后缀 |
| 完整文件名 | 鼠标悬停或键盘聚焦文件名时，通过 Tooltip 展示完整文件名 |
| 文件大小 | 最多保留两位小数，单位使用 KB、MB 或 GB |
| 上传进度 | 上传中展示百分比进度，取值范围为 0% 至 100% |
| 错误原因 | 错误附件直接展示具体错误原因，不只使用颜色区分 |

文件名省略示例：

```text
原文件名：2026年第三季度海外市场销售数据最终确认版.xlsx
省略展示：2026年第三季…版.xlsx
```

文件大小展示规则：

1. 小于 1 MB 时使用 KB。
2. 大于等于 1 MB 且小于 1 GB 时使用 MB。
3. 大于等于 1 GB 时使用 GB。
4. 最多保留两位小数，末尾无效的 `0` 不展示。

### 4.11 图片处理与展示

1. `png`、`jpg`、`jpeg`、`webp` 直接用于预览和 AI 读取。
2. 其他图片格式必须转换为 PNG 或 JPG，转换后才能发送。
3. 原始文件继续保留，供用户查看文件信息和下载。
4. 转换后的标准图片用于界面预览和 AI 读取，不单独显示为另一个附件，也不占用附件名额。
5. 输入框附件区和用户消息气泡均展示转换后的图片。
6. 用户点击图片后打开转换后的大图预览；点击下载时下载原始文件。
7. 转换过程中，附件状态显示“图片处理中”，消息暂时不能发送。
8. 转换失败时，附件显示错误状态并阻止发送；用户需要移除该图片或重新上传。

### 4.12 视频缩略图

1. 视频上传后提取视频封面并展示缩略图。
2. 封面提取成功后，在输入框附件区和用户消息气泡中使用同一封面。
3. 封面提取失败时，展示视频类型图标和文件名。
4. 封面提取失败不阻止消息发送。

### 4.13 附件操作

桌面端附件卡片在 Hover 或键盘聚焦时显示操作按钮；移动端始终显示更多操作入口。

| 操作 | 规则 |
|---|---|
| 移除 | 从附件区移除文件；若正文中存在该文件引用，同步移除对应引用 |
| 取消上传 | 终止该附件上传并从附件区移除 |
| 重试 | 对校验规则未变化的上传失败附件重新发起上传 |
| 预览 | 图片打开大图预览；其他可预览文件打开文件预览 |
| 下载 | 已上传成功的附件允许下载原文件 |

## 5. 大文本粘贴

### 5.1 判断规则

1. 用户粘贴文本时，系统计算“当前正文字符数 + 本次粘贴文本字符数”。
2. 计算结果小于或等于 20,000 个字符时，将内容插入当前光标位置。
3. 计算结果超过 20,000 个字符时，本次粘贴内容不写入正文。
4. 系统将本次粘贴的完整内容转换为一个 TXT 文件。
5. 大文本转换不设置字符数上限，不截断、不删除、不改写文本。
6. 大文本模块不设置独立大小限制；生成的 TXT 适用“其他文件最大 1 GB”的附件规则。
7. 输入框中原有正文保持不变。

### 5.2 TXT 生成规则

1. 生成的 TXT 必须能够正常显示中英文、换行和特殊字符，不得出现乱码。
2. 文件扩展名固定为 `.txt`。
3. 文件名格式为 `粘贴文本_YYYYMMDD_HHmmss.txt`。
4. 英文界面中的文件名格式仍使用 `pasted_text_YYYYMMDD_HHmmss.txt`。
5. 文件内容必须与标准化为纯文本后的剪贴板内容完全一致。
6. 换行、空格、制表符和特殊字符必须保留。
7. 一次大文本粘贴生成一个 TXT 附件。
8. 生成完成后立即进入标准附件校验和上传流程。
9. TXT 使用普通文本附件卡片，不使用独立的大文本卡片。
10. TXT 计入 20 个顶层附件上限。

### 5.3 特殊情况

1. 当前已有 20 个附件时，不生成 TXT，并展示附件数量超限提示。
2. TXT 文件生成失败时，不修改正文，不创建附件卡片，并展示生成失败提示。
3. TXT 文件超过 1 GB 时，按附件大小超限处理。
4. 相同文本可以重复粘贴，每次均生成新的 TXT 附件。
5. TXT 上传失败时，保留失败附件卡片，允许重试或移除。

## 6. 复制、粘贴、撤销与还原

### 6.1 复制与粘贴

1. 支持系统标准快捷键 `Ctrl/Cmd + C` 和 `Ctrl/Cmd + V`。
2. 从网页或文档粘贴富文本时，只保留文字、换行和列表层级。
3. 字体、字号、颜色、背景、脚本和不可见样式全部移除。
4. 粘贴图片、截图、文件或文件夹时，按照附件上传处理。
5. 粘贴 URL 时按照普通文本处理，不自动转换为附件。
6. 普通文本插入当前光标位置。
7. 存在选中文本时，普通粘贴内容替换选中内容。
8. 粘贴后正文超过 20,000 个字符时，按照“大文本粘贴”规则转换为 TXT 附件。

### 6.2 撤销单元（粒度）规则

| 操作类型 | 撤销粒度 |
|---|---|
| 英文、数字及符号连续输入 | 相邻输入间隔不超过 1 秒时合并为一个单元；停顿超过 1 秒、移动光标或改变选区后开启新单元 |
| 中文输入法输入 | 拼音组词阶段不产生撤销记录；文字确认上屏后进入连续输入单元。相邻上屏间隔不超过 1 秒时继续合并，超过 1 秒后开启新单元 |
| 粘贴或剪切 | 每次操作为一个单元，一次撤销恢复到操作前状态 |
| 连续删除 | 连续按退格键或 `Delete` 且间隔不超过 1 秒时合并为一个单元 |
| 删除选中文字 | 一次删除为一个单元，一次撤销恢复全部被删除文字 |
| 替换选中文字 | 删除原文字和插入新文字合并为一个单元 |
| 插入或删除技能、MCP、店铺及工作流引用 | 每次操作为一个单元；撤销时整体移除或整体恢复引用标签 |
| 换行 | 每次换行为一个单元 |

中文输入示例：连续上屏“选品”“技能”，两次上屏间隔不超过 1 秒时，一次撤销删除“选品技能”；若两次上屏间隔超过 1 秒，第一次撤销只删除“技能”。

### 6.3 撤销与还原规则

1. `Ctrl/Cmd + Z` 撤销；`Ctrl/Cmd + Shift + Z` 还原；Windows 同时支持 `Ctrl + Y`。
2. 输入框失去焦点时结束当前连续输入或连续删除单元。
3. 撤销后再次编辑正文，清空还原记录。
4. 每个草稿最多保留 100 个撤销单元，超出后删除最早记录。
5. 附件和消息引用不进入正文撤销记录；大文本转成 TXT 后通过“移除附件”处理。
6. 切换会话、刷新页面或消息发送成功后，清空撤销和还原记录。

## 7. 消息引用与回复

### 7.1 引用规则

1. 用户消息和 AI 消息均提供“引用”操作。
2. 用户选择消息中的局部文字后，可以引用选中内容。
3. 每条待发送消息最多引用一条历史消息。
4. 引用其他消息时，替换当前已经选择的引用。
5. 用户可以在发送前移除引用。

### 7.2 引用展示

1. 引用成功后，在输入框上方展示引用条。
2. 引用条展示消息发送者和引用摘要。
3. 引用摘要最多展示 200 个字符。
4. 超过 200 个字符时，在末尾展示省略号。
5. 点击引用条后，页面定位到原消息并高亮 2 秒。
6. 引用条提供移除按钮。

### 7.3 引用发送

1. 发送后的用户消息气泡展示引用摘要。
2. Agent 可以读取被引用消息的完整内容和用户选中的文本范围。
3. 引用消息不会自动携带原消息中的附件和资源引用。
4. 原消息已删除、不可访问或不属于当前会话时，引用状态变为失效。
5. 存在失效引用时禁止发送。
6. 用户移除失效引用后恢复发送。

## 8. 输入草稿自动保存

### 8.1 草稿内容

每个会话独立保存以下内容：

1. 正文内容。
2. 光标位置。
3. 当前消息引用。
4. 已上传成功的附件及其状态。
5. 上传失败附件的本地展示信息。
6. 已选择的技能、MCP、店铺和工作流引用。

### 8.2 保存时机

1. 用户停止编辑 1 秒后自动保存。
2. 添加、删除或完成附件上传时立即保存。
3. 添加或删除消息引用时立即保存。
4. 添加或删除资源引用时立即保存。
5. 切换会话时立即保存。
6. 页面刷新、关闭或进入后台时立即保存。
7. 自动保存过程不得打断用户输入。

### 8.3 恢复与清理

1. 用户进入会话时自动恢复最近草稿。
2. 同一账号在多个设备存在不同草稿时，恢复最后保存的草稿。
3. 草稿保留 7 天。
4. 消息发送成功后立即删除对应草稿。
5. 消息发送失败时保留草稿。
6. 会话被删除时同步删除草稿。
7. 草稿中的附件已失效时，保留文件名和失效状态，不恢复为可发送附件。
8. 用户必须移除或重新上传失效附件后才能发送。
9. 草稿恢复失败时，不覆盖用户当前已经输入的内容。

## 9. 技能、MCP、店铺及工作流引用

### 9.1 入口与菜单层级

技能支持 `/` 快捷唤起，也支持从 `+` 菜单选择。其他资源仅通过 `+` 菜单选择。

点击 Chatbox 左下角的 `+` 按钮后，展示以下菜单：

| 菜单项 | 进入后的操作 |
|---|---|
| 添加文件 | 选择本地文件或文件夹，进入附件上传流程 |
| 技能 | 打开技能选择页 |
| MCP | 打开 MCP 选择页 |
| 店铺 | 打开店铺选择页 |
| 工作流 | 打开工作流选择页 |

菜单键盘导航规则：

| 操作 | 结果 |
|---|---|
| `Enter` 或空格键 | 在 `+` 按钮聚焦时打开菜单 |
| `↑`、`↓` | 移动高亮项 |
| `Enter` 或 `→` | 进入当前分类或选择当前结果 |
| `←` | 返回上一级菜单 |
| `Esc` | 选择页返回上一级；一级菜单直接关闭 |
| `Tab`、`Shift + Tab` | 按界面顺序移动焦点 |

### 9.2 技能引用

#### 9.2.1 数量与入口

1. 单条消息最多引用 3 个技能。
2. 同一技能只能引用一次。
3. 用户可以通过 `/` 或 `+` 菜单中的“技能”进入技能选择。
4. 达到 3 个后，不允许继续选择技能，并展示数量上限提示。

#### 9.2.2 `/` 唤起条件

输入 `/` 时，满足以下任一条件即打开技能面板：

1. 光标位于空行。
2. 光标位于行首。
3. 光标前一个字符为空格或换行。

光标前一个字符为普通文字、数字、字母或符号时，`/` 作为普通文本输入，不打开技能面板。

#### 9.2.3 `/` 搜索规则

1. 输入 `/` 后立即打开技能面板，默认展示最近使用的技能。
2. 面板不展示独立搜索框，输入焦点始终保留在 Chatbox。
3. `/` 后连续输入的内容作为搜索词，技能列表随输入实时过滤。
4. 中文输入法组词期间不更新结果，文字确认上屏后再过滤列表。
5. 输入空格时结束搜索，面板关闭，`/`、搜索词和空格保留为普通文本。
6. 搜索结果为空时自动关闭面板，`/` 和搜索词保留为普通文本。
7. 按 `Esc`、移动光标、改变选区或点击 Chatbox 之外区域时关闭面板，已输入内容保持不变。
8. 删除搜索词时实时恢复结果；删除 `/` 后关闭面板。

#### 9.2.4 `/` 面板导航

面板打开后默认高亮第一项，输入焦点仍在 Chatbox。

| 操作 | 结果 |
|---|---|
| `↑`、`↓` | 移动高亮项，到达首项或末项后停止 |
| `Enter` | 选择高亮技能，不发送消息 |
| `Esc` | 关闭面板，保留 `/` 和搜索词 |
| `Backspace` | 删除搜索词并更新结果；删除 `/` 后关闭面板 |
| 鼠标悬停 | 高亮对应技能 |
| 鼠标点击 | 选择对应技能 |

中文输入法处于候选词选择状态时，方向键和 `Enter` 只操作输入法候选词。候选词确认上屏后恢复面板导航。

#### 9.2.5 `+` 菜单选择技能

1. 进入技能选择页后，焦点位于搜索框。
2. 输入关键词后实时过滤，每次最多展示 20 条结果。
3. 默认展示最近使用的技能。
4. 选择技能后关闭选择页，并在 Chatbox 中添加技能标签。

#### 9.2.6 技能选择结果

1. 通过 `/` 选择技能时，用技能标签替换 `/` 和搜索词。
2. 通过 `+` 菜单选择技能时，直接添加技能标签。
3. 标签展示技能图标、名称和移除按钮。
4. 选择完成后，光标位于标签之后，用户可以继续输入正文。
5. 技能不可用或无权限时不能选择，并在技能项中说明原因。

### 9.3 MCP 引用

1. MCP 仅通过 `+` 菜单中的“MCP”进入选择。
2. 单条消息最多引用 3 个 MCP。
3. 同一 MCP 只能引用一次。
4. 选择页默认展示已接入的 MCP，并支持搜索；每次最多展示 20 条结果。
5. 未授权的 MCP 展示授权入口，完成授权后才能选择。
6. 达到 3 个后，不允许继续选择，并展示数量上限提示。
7. 选择成功后，在 Chatbox 中添加 MCP 标签。

### 9.4 店铺引用

1. 店铺仅通过 `+` 菜单中的“店铺”进入选择。
2. 单条消息最多引用 3 个店铺。
3. 同一店铺只能引用一次。
4. 选择页只展示当前账号有权访问的店铺，并支持按店铺名称和平台搜索。
5. 店铺项展示平台图标、店铺名称和授权状态。
6. 达到 3 个后，不允许继续选择，并展示数量上限提示。
7. 选择成功后，在 Chatbox 中添加店铺标签。

### 9.5 工作流引用

1. 工作流仅通过 `+` 菜单中的“工作流”进入选择。
2. 单条消息最多引用 1 个工作流。
3. 已引用工作流时，必须先移除当前工作流，才能选择其他工作流。
4. 选择页只展示当前可用的工作流，并支持按名称搜索。
5. 工作流项展示名称和简要说明。
6. 选择成功后，在 Chatbox 中添加工作流标签。

### 9.6 添加文件

1. 点击 `+` 菜单中的“添加文件”后，选择上传本地文件或文件夹。
2. 文件进入第 4 章定义的附件上传流程。
3. 文件计入附件数量上限，不计入技能、MCP、店铺或工作流的引用数量。

### 9.7 引用标签通用规则

1. 标签展示资源类型图标、名称和移除按钮。
2. 点击标签打开对应资源详情。
3. 用户可以在发送前移除任意标签。
4. 插入或删除标签分别构成一个完整撤销单元，撤销时整体移除或恢复。
5. 消息发送后保留引用类型、名称和版本，历史消息中可以追溯引用来源。

### 9.8 权限与有效性

1. 用户选择资源时立即校验访问权限。
2. 需要授权的资源完成授权后才能选择。
3. 无权限、已停用、已删除或已过期的资源不可选择。
4. 消息发送前再次校验全部引用。
5. 任一引用校验失败时禁止发送，并在对应标签上说明原因。

## 11. 验收标准

### 11.1 文本输入

1. 正文达到 20,000 个字符后不能继续通过键盘输入。
2. 中文输入法选词时按 `Enter` 不会发送消息。
3. 正文达到 18,000 个字符后展示实时字符计数。
4. 空正文且没有附件或引用时不能发送。
5. 发送失败后正文、附件和引用完整保留。
6. 间隔不超过 1 秒的连续输入或连续删除可一次撤销。
7. 中文输入法连续上屏且相邻间隔不超过 1 秒时，合并为一个撤销单元。
8. 撤销后重新编辑正文会清空还原记录。
9. 技能、MCP、店铺及工作流引用只能整体撤销或恢复，不会出现部分标签残留。

### 11.2 附件上传

1. 点击、拖拽、多选、剪贴板和文件夹上传均可用。
2. 白名单内文件允许进入上传流程，白名单外文件不能上传。
3. 单条消息最多保留 20 个顶层附件。
4. 批量超限时只添加能够补足到 20 个的前 N 项。
5. 图片大小上限为 100 MB，视频、压缩包、文件夹和其他文件上限为 1 GB。
6. 文件夹最大深度为 10 层，空文件和空目录允许上传。
7. 相同文件可以重复上传，每次上传均作为独立附件并计入数量上限。
8. 错误附件排在附件区最前面，并展示具体错误原因。
9. 非标准图片转换成功后，使用转换后的 PNG 或 JPG 进行预览和 AI 读取，同时保留原始文件供下载。
10. 非标准图片转换失败时不能发送，附件必须被移除或重新上传。
11. 视频封面提取失败时降级为视频图标，不阻止发送。
12. 存在校验失败或上传失败附件时不能发送消息。
13. 移除附件时同步移除正文中的对应文件引用。

### 11.3 大文本粘贴

1. 粘贴后正文不超过 20,000 个字符时，内容插入正文。
2. 粘贴后正文超过 20,000 个字符时，本次完整粘贴内容转换为 TXT。
3. 大文本转换不设置字符数限制，不截断原内容。
4. 生成的 TXT 按普通附件校验、上传、展示和发送。
5. TXT 生成失败时不向正文插入任何部分内容。
6. TXT 文件计入 20 个附件上限，并适用单文件 1 GB 上限。

### 11.4 草稿与引用

1. 页面刷新或切换会话后可以恢复 7 天内的草稿。
2. 消息发送成功后清除草稿，发送失败时保留草稿。
3. 每条消息最多引用一条历史消息、3 个技能、3 个 MCP、3 个店铺和 1 个工作流。
4. 失效消息引用和失效资源引用会阻止发送。
5. 资源在选择时和发送前分别执行一次权限校验。
6. `/` 仅在空行、行首或前一个字符为空格或换行时打开技能面板。
7. Slash 技能面板打开后，输入焦点保持在 Chatbox，面板中不出现独立搜索框。
8. `/` 后输入空格、搜索无结果或按 `Esc` 时关闭面板，并保留已经输入的普通文本。
9. 技能面板支持方向键移动、`Enter` 选择、`Esc` 关闭和 `Backspace` 更新搜索结果。
10. `+` 菜单包含添加文件、技能、MCP、店铺和工作流。
11. 技能或资源选择成功后以完整标签展示，并支持整体撤销和恢复。

### 11.5 范围与国际化

1. Agent 工作状态由单独的会话状态需求定义，不在 Chatbox 中重复定义。
2. 所有错误、限制、状态和操作提示均提供中文和英文版本。
3. 桌面端和移动端不存在输入框、附件区、消息引用和资源引用相互遮挡的问题。
