# AI 消息气泡 PRD

版本：V1.0  
适用端：网页端（Web）  
适用范围：通用智能体、生图智能体的 AI 回复

## 1. 需求范围与布局

AI 消息按以下顺序展示，有对应内容时显示该区域：

|顺序|区域|内容|
|---|---|---|
|1|过程区|思考状态、耗时、公开摘要及工具调用记录|
|2|正文区|流式 Markdown 回复|
|3|产物区|本轮 AI 文件产物|
|4|执行状态与异常组件|上下文压缩、网络重连、模型异常等提示及恢复操作|
|5|操作区|复制、点赞、点踩、分享、新建分支|
|6|信息区|消息结束时间及实际积分消耗|

文件能力沿用《AI文件生成与处理能力需求文档》，文件预览及操作沿用《文件预览及操作需求文档》，图片及视频的异常提示沿用媒体需求。本文定义 AI 气泡的展示与操作入口。

## 2. 回复正文

1. 支持流式 Markdown，包含文本、标题、列表、引用、表格、代码块、流程图及链接。
2. 渲染失败时展示对应原文或源码，其他内容保持正常。
3. 默认跟随最新输出；用户向上滚动后暂停跟随，显示“回到最新”，点击后恢复跟随。
4. 正文中的文件引用与产物卡片指向同一文件。

## 3. 思考与工具过程

### 3.1 状态与耗时

|状态|展示|
|---|---|
|执行中|思考中 · {duration}|
|正常结束|思考已完成 · {duration}|
|用户停止|已停止 · {duration}|

1. 耗时按服务端过程开始、结束时间计算，包含工具执行；执行中按秒更新。
2. 少于 60 秒显示“12秒”，达到 60 秒显示“1分08秒”；英文使用“12s”“1m 08s”。
3. 刷新或返回会话时恢复服务端记录的状态及耗时。
4. 异常结束时保留过程记录和实际耗时，异常提示由独立组件展示。

### 3.2 展开与收起

1. 有公开过程内容时，执行中默认展开，回复结束后自动收起，用户可再次展开。
2. 执行中用户手动收起后保持该选择；没有公开内容时，仅显示状态及耗时。
3. 展开区域仅展示可公开摘要和工具记录。工具记录按调用顺序排列，展示名称、状态及结果摘要。
4. 工具状态为执行中、已完成、失败、已取消；状态更新在原记录上完成，点击可展开详情。

## 4. 文件产物展示

1. 本轮成功文件在正文末尾统一平铺，空间不足时换行，按完成时间正序排列。
2. 同一文件本轮多次更新时，展示最新成功结果一次。
3. 卡片展示文件名、类型图标及大小；图片用缩略图，视频用封面及播放标识，文件夹显示内部文件数量。
4. 点击进入对应预览或播放，卡片提供下载入口；操作及异常规则沿用《文件预览及操作需求文档》。
5. 当前轮默认全部展示。开始下一轮或重新进入会话后，历史回复默认显示第一个文件，其余显示“展开更多”，展开后可收起。
6. 文件失效时保留卡片及名称；失败文件在过程区反馈，成功文件继续展示。

## 5. 消息操作

回复结束后，按已有内容展示可用操作：

|操作|规则|
|---|---|
|复制|复制正文 Markdown 原文，范围为回复正文；正文为空时禁用|
|点赞、点踩|两者互斥，再次点击可取消，切换时替换原选择|
|分享|进入本条回复的分享能力，规则由《分享需求》承接|
|新建分支|以本条回复为起点创建分支，规则由会话分支需求承接|

正常完成、用户停止及执行失败后，均可对已有正文使用上述可用操作。

## 6. 时间与积分

1. 正常完成、用户停止或执行失败后，展示服务端记录的本轮结束时间。
2. 时间按用户时区转换，显示到分钟，中英文格式沿用用户消息气泡的时间规则。
3. 积分结算完成后展示“消耗 N 积分”，仅使用本轮实际值；实际值为 0 时显示 0。
4. 结束时间与积分在同一信息区展示，计费及结算规则由积分需求承接。

## 7. 执行状态与异常组件

### 7.1 展示位置

- **AI 气泡位置**：使用独立组件，位于正文及产物区下方、消息操作区上方。展示 AI 自动处理的进度及处理失败结果，与思考过程的展开收起分别控制。
- **聊天框上方**：展示需要用户处理的账户问题，如积分不足、登录失效，并提供对应操作入口。

### 7.2 情况、位置与操作

|情况|显示位置|中文提示|English|操作|

### 7.3 处理规则

1. AI 可自动处理的情况在会话中展示过程，成功后继续原任务并清除提示，失败后仍在同一位置展示结果和操作入口。
2. 网络中断最多自动重连 5 次，显示当前次数；失败后停止自动重连，提供刷新。刷新可开始新一轮最多 5 次重连。
3. 刷新复用原任务，查询最新内容及状态；重新执行仅用于服务端已确认结束的任务。已有正文、过程及成功文件保留。
4. 上下文压缩成功后继续任务；压缩失败时自动截断较早上下文，优先保留当前用户请求、必要的执行规则及当前步骤所需信息，按可用上下文长度继续执行。该失败不终止任务，不要求用户重新执行。模型恢复及任务超时由执行服务按技术评估处理。
5. 积分不足或登录失效时，聊天框上方提示用户处理。处理完成后重新检查，按原任务状态恢复或由用户重新发起；积分获取及登录内部规则由专项能力承接。
6. 同一位置展示一条当前需要处理的提示。暂时没有新正文但任务仍运行时，保持执行中。
   上下文截断仅调整本轮发送给模型的内容，历史消息及文件记录保持原样；后续需要较早资料时按需重新读取。
7. 工具局部失败保留调用记录，整轮可继续；能力不支持由 AI 正常回复。文件、分享等异常沿用对应需求。

## 9. 验收标准

1. 气泡各区域顺序正确，流式输出、渲染降级及滚动跟随符合规则。
2. 公开过程的展开收起、耗时及工具状态正确，刷新后可恢复。
3. 产物排序、重复更新合并及历史折叠正确，点击进入对应文件能力。
4. 回复结束后操作可用，复制范围、反馈互斥及专项入口正确。
5. 正常完成、停止及失败的结束时间正确，积分使用结算后的实际值。
6. 自动处理进度和失败结果在 AI 气泡位置的独立组件展示；积分不足和登录失效在聊天框上方展示。
7. 重连最多 5 次，失败后提供刷新，刷新恢复原任务，重新执行仅用于确认结束的任务。
8. 上下文压缩失败时自动截断并继续，不阻断用户；截断优先保留当前请求及必要信息，历史消息展示保持原样。其他异常按表处理。
