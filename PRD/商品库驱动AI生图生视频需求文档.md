# 商品库驱动 AI 生图生视频需求文档

版本：v1.0　日期：2026年10月31日　状态：需求评审稿

适用对象：商品库、创作平台、ERP／商城、模型服务、计费及数据团队。

## 1 产品目标与决策边界

围绕商品和 SKU，将 ERP 已有资料转为可核对的创作输入，优先交付电商刊登套图；创作结果自动关联商品，经人工选用后导出或回传 ERP。视频先验证商品外观／卖点展示和数字人口播，验证后再扩大能力范围。

首期应跑通：**导入商品 → 补齐资料 → 确认 SKU 与参考图 → 选择刊登方案 → 生成与修改 → 人工选用 → 商品资产沉淀 → 导出或回传 → 用量与费用追踪。**

### 1.1 会议共识与本次规划

| 类型 | 内容 | 产品处理 |
| --- | --- | --- |
| 会议已明确 | 刊登套图近期优先；内部需求优先；以商品库串联资产 | 作为本次主线 |
| 会议已明确 | 先工作流验证，再工程化；平台、API、MCP、Skill 同步考虑 | 共用业务对象及任务服务，按场景逐项开放 |
| 会议优先验证 | 商品展示、数字人口播；继续验证爆款复刻 | 提供受控试点，分别验收 |
| 本次产品方案 | ERP 与创作平台职责、字段映射、快照、资产状态、回传及计费规则 | 以下条款供评审确认，不作为会议原有结论 |

不在近期新增承诺内：完整视频编辑器、复杂人货互动、完整 POD 生产链路、包装印刷文件交付、重型画布、复杂图层、社媒多账号发布与效果闭环。现有 POD／包装概念入口维持已有范围，不因入口存在而承诺生产交付。

### 1.2 目标用户与业务结果

| 用户 | 主要任务 | 应获得的结果 |
| --- | --- | --- |
| 内部刊登运营 | 从 ERP 选品，批量补图、上新、多市场适配 | 知道每个 SKU 缺什么，获得用途明确的套图及交付记录 |
| 内部视频团队 | 使用商品素材制作展示或讲解视频 | 先确认脚本与参考画面，再生成可审核的视频 |
| 商品／设计人员 | 维护事实资料、参考素材、品牌规范，修改结果 | 商品事实和创意表达分开维护，修改可追溯 |
| 模板及业务运营 | 维护支持组合、模板、规则，跟进失败案例 | 清楚哪些组合经验证、哪些仅可试用 |
| 企业管理员／财务 | 管理授权、额度，核对用量与内部结算 | 按业务线、来源及账期查看获授权的用量和费用 |
| 外部系统／智能体 | 提交生成、查询任务、取得结果 | 使用与 Web 相同的权限、任务和计量体系 |

以下为项目代码和现有需求中的本地 Demo 能力，不能直接视为生产系统已接通。

| 能力 | 当前表现 | 本次处理 |

| SKU 档案 | 规格、颜色、产品／包装尺寸、外观、工艺、卖点和素材维护 | 保留 SKU 维度，补齐外部 ID、来源及字段确认 |

| 产物归档 | 商品图／其他素材／参考素材，按平台、站点、语言、用途和 SKU 关联 | 改为先自动关联草稿，再由用户选用；引用不复制底层文件 |
| 素材空间 | 个人／企业空间及上传、预览、下载等演示 | 复用信息结构，生产权限按现有多租户需求实现 |
| 视频 | 场景、参数、方案确认及结果占位 | 作为交互基础，接入模型前不标记为真实生成能力 |

当前表格导入为 XLSX／CSV／TSV、5MB、最多 500 数据行；SKU 档案演示为每 SKU 最多 30 张图片、5 条视频。这些是当前入口限制，不作为全平台目标容量。ERP 表格原型支持格式和行数不同，需分别展示各入口限制。

### 2.2 ERP 采集箱原型

所提供的《采集箱交互原型_v2.29.html》展示了货盘、1688 链接、Amazon ASIN、Excel、图采等商品来源；商品行展开子 SKU，支持单 SKU／全部／批量认领、失败查看与重试、商品编辑和导出。

| 原型特点 | 对本次需求的影响 |
| --- | --- |
| 商品与子 SKU 分层，认领状态由 SKU 汇总 | 必须保留外部商品 ID、SKU ID；认领状态不等于创作状态或访问权限 |
| 商品级成分／功效，SKU 级规格、重量、尺寸、价格等 | 导入后分层维护；不能把商品级功效直接当作已确认卖点 |
| 图采最多 5 张，辅助图只供分析、不入商品图集 | 创作侧增加辅助图留存与用途确认，避免视频参考丢失；ERP 接口未返回时提示补传 |
| AI 推断数值要求改为数字，OCR 值可保留 | 创作侧仍需记录来源及人工确认；格式为数字不代表实测准确 |
| 类目存在源站类目、映射类目、待映射／申请中等状态 | 保留原类目与映射结果；未映射不一律阻断建档或通用创作 |
| 重复链接提示覆盖已有商品 | ERP 自身策略由 ERP 负责；创作侧同步不得据此覆盖人工补充和历史快照 |
| Excel 提示 8 项必填，图采提示并校验 7 项 | 按渠道及模板版本维护字段规则，联调时核实，不能合成统一必填数量 |

原型中的平台权限、违规词过滤、精度百分比及接口字段注释仅作为设计线索，不作为已验证的平台规则或正式接口契约。尤其不得依赖刊登侧自动过滤来保证生成内容正确。

### 2.3 系统职责

| 系统 | 负责范围 | 与商品库的关系 |
| --- | --- | --- |
| ERP／商城 | 来源采集、商品及 SKU 主数据、认领、店铺与刊登任务、平台回执 | 提供授权商品和资料，接收经选用的内容 |
| 创作商品库 | 商品映射、创作补充资料、事实确认、参考素材、创作结果与记录 | 组织创作资产，不接管库存、交易、物流和 ERP 认领 |
| 创作工作台／任务服务 | 方案确认、模型任务、结果修改、质量反馈、成本及状态 | 使用不可变输入快照，结果回到商品 |
| 模板／知识／素材库 | 模板与规则版本、品牌规范、文件实体及授权 | 同一资产复用，保留版本及可访问范围 |

首期优先接入 ERP／商城已有商品接口，不另建一套采集服务。接口未就绪时可通过当前表格／手动方式试点；此时交付方式明确显示“导出文件”，不能显示“已同步 ERP”。

## 3 分期与范围

P0 为刊登闭环必需；P1 为独立验证和后续增强；P2 为专项评估。优先级不代表上线日期，试点可与 P0 建设并行。

| 阶段 | 范围 | 交付与进入下一阶段的条件 |
| --- | --- | --- |
| 范围确认 | 真实需求调研、成本价格、首批支持组合、4—5 项修图候选、接口盘点 | 支持矩阵、样本集、字段契约、计费方案、负责人明确 |
| P0 刊登试点 | 商品映射和输入检查；套图方案与生成；单图修改；批量任务；自动关联、选用和导出；用量成本记录 | 用真实商品完成端到端验收；接通授权数据、任务与资产持久化 |
| P0 接口交付 | 同一套图能力的任务提交／查询／结果服务，MCP／Skill 适配；ERP 回传 | 生成接口随已验证场景交付；ERP 写入依赖接口确认，可与导出分批交付 |
| P1 视频及增强 | 商品展示、数字人口播试点；更多模板与批量本地化；爆款复刻分类验证 | 视频有独立效果、时长、成本和稳定性评测；各场景分别决定是否开放 |
| P2 专项 | 混剪、翻译、简单裁剪接入；POD、包装生产、复杂编辑、社媒闭环 | 单独完成可行性和投入产出评审后排期 |

旧架构文档中的广泛能力是候选方向，本次以此表收敛近期新增范围。历史工作流仅维持已验证使用，不把全部旧入口纳入首期验收。

## 5 商品资料与输入管理

### 5.1 商品与 SKU 映射 P0

需求编号：PRD-01。

使用“当前身份／企业范围＋来源系统＋外部商品 ID”定位同一来源商品，使用外部 SKU ID 定位变体；商品编码和 SKU 货号用于展示、搜索及冲突提示，不单独作为跨系统去重依据。

| ERP 概念 | 创作商品库字段或对象 | 规则 |
| --- | --- | --- |
| 产品 ID、父商品编码 | 外部商品映射、内部商品 ID、商品编码 | 外部主键与业务编码分别保存，源站 ID 不替代 ERP 内部产品 ID |
| SKU ID、SKU 货号、规格属性 | 外部 SKU 映射、内部 SKU ID、变体属性 | 保留颜色、规格、数量等结构；不可按标题自动合并 |
| 中英文标题、品牌、描述 | 商品名称、原文语言、品牌、描述 | 翻译稿单独保存，不反写源标题 |
| 成分／材质、功效 | 材质／成分、候选卖点 | 保存原文；经人工确认后才进入正式卖点表达 |
| 产品尺寸、包装尺寸、重量 | 分开的数值、单位、来源与确认状态 | 产品尺寸用于相应展示；包装尺寸不替代产品尺寸；估算保留为待核实 |
| 来源类型、货源、源链接、批次号 | 来源元数据 | 来源平台与内容目标平台分开，1688 商品可生成其他平台版本 |
| 源站类目、系统类目及映射状态 | 类目映射记录 | 商品类目与目标平台类目分别维护 |
| 主图、SKU 图、视频、图采辅助图 | 素材实体与商品／SKU 关联 | 保留原始角色；只有明确适用的参考进入生成 |
| 认领状态、采集状态、价格 | 来源业务状态及可选资料 | 不直接驱动创作状态；价格不自动成为促销文案 |

同一商品只选部分 SKU 导入时，预览明确导入范围；后续导入其他 SKU 合并到已映射商品。不同来源疑似同款只提示，由有权限人员确认映射，不自动并档。未认领 SKU 是否允许接入由 ERP 授权决定，创作平台不通过生成操作自动认领。

### 5.2 同步与冲突处理 P0

需求编号：PRD-02。

1. 首次连接由有权限用户选择来源及范围，预览商品、SKU、新增／更新／冲突数量后导入；记录批次和操作者。
2. 来源字段保留源版本，创作补充说明、品牌规范、人工卖点、素材用途由创作侧维护。首期只回传选用资产，基础事实字段不双向自动覆盖。
3. 默认补齐未填字段；同一字段已被人工修订时显示新旧值，由用户保留本地或采用来源值。来源字段无本地覆盖的，可更新来源副本并触发必要的重新确认。
4. 源字段为空不清空已有有效值。删除、SKU 合并、停用等通过明确变更事件处理；不可凭一次分页缺失推断删除。
5. 名称、商品事实、规格、卖点等变化使相关核对失效；参考图变化重新检查可用性及适用范围。旧任务和旧产物仍指向原快照，并显示来源资料已更新。
6. 同一批次／请求重复提交不重复建档；失败保留原数据和错误明细，允许按失败项重试。接口不可用时显示失败／待重试，不显示同步成功。
7. 源商品停用后禁止新的来源任务；运行中任务保留原快照，结果仅可按有效权限查看，后续交付前重新校验。商品归档不等于物理删除资产。

### 5.3 字段来源与人工确认 P0

需求编号：PRD-03。

每项关键事实记录：值、单位、来源类型、来源记录或素材、最近版本、确认状态、确认人和时间。来源区分 ERP／商城、人工、OCR、AI 推断、生成产物；OCR 识别不自动代表内容准确。

AI 推断区间可以作为待核实草稿保存，不可直接用于精确尺寸图、性能数字或事实性承诺。将区间改为单个数字仍需用户提供测量值或有效依据。无尺寸时可取消尺寸图角色继续生成其他图片；不得猜一个尺寸补齐。

人工确认绑定本次事实与引用素材版本。保留现有整份资料核对方式，首期增加变更提示；需要逐字段确认的尺寸、成分、性能数据不得被统一勾选掩盖。确认商品资料不等于平台审核或实际合规通过。

### 5.4 参考素材 P0

需求编号：PRD-04。

素材角色至少包括主视图、侧面／背面、细节、尺寸依据、包装／标签、生活场景、风格参考及视频素材。商品共用图与 SKU 专属图分别设置；其他 SKU 专属图不得被自动引用。

生成前预览本次参考清单，允许勾选和排除。明确展示生成参考，不能把生成图默认认定为真实商品依据。已有创作产物只有经用户执行“设为参考”并核对适用 SKU 后，才能进入参考范围；派生链持续保留。

图采辅助图可选择“保留为资料依据”“设为创作参考”“仅本次分析”，默认保留方式与 ERP 确认后配置；保留不自动进入刊登图集。当前 ERP 没有返回这些文件时，显示具体缺口，不以主图数量冒充多视角齐备。

## 6 刊登套图与轻量修改

### 6.1 支持组合与方案确认 P0

需求编号：PRD-05。

按“平台×市场／站点×品类×二级类目”维护支持矩阵，另行设置内容语言。每个组合记录支持状态、模板、规则版本、输入要求、示例、能力限制和维护人；首批组合由内部真实商品决定。

支持状态为“专项已验证”“通用试用”“暂不支持”。专项无匹配时可以明确切到通用试用，不得静默使用美妆模板处理其他类目；暂不支持的场景可保存草稿，不能提交对应生成。

用户选择目标平台、市场、语言、SKU 后查看套图方案：图片角色、数量、顺序、比例／尺寸、文案、引用素材和费用预估。初始角色候选为主图、场景图、卖点图、尺寸图、SKU 组合图、详情素材，实际选项由支持组合决定，不要求每套固定六张。

模板必须包含适用范围、必需资料、输出角色、内容限制、参考案例、提示词及版本。规则优先级为商品事实及适用硬规则优先，品牌要求、模板及用户创意不得覆盖事实；冲突时展示具体冲突，阻断受影响输出或让用户取消该要求，不能自动忽略。

### 6.2 生成流程 P0

需求编号：PRD-06。

选择商品及 SKU → 选择支持组合 → 补齐资料 → 确认参考图与事实 → 选择并调整套图方案 → 查看预计费用 → 提交 → 查看逐张结果 → 修改／重做 → 人工选用 → 导出或回传。

单 SKU 为默认任务单位。多 SKU 批量时每个 SKU 有独立输入快照和参考图；SKU 组合图使用独立“组合”任务，明确 SKU、件数及配件清单，不能把多个 SKU 的参考图混成单品图。

结果卡片展示用途、SKU、方案版本、生成状态、检查结果及修改入口。套图展示“计划／成功／待修改／失败”数量，缺少必需图片时可导出已有结果，但标注“部分交付”，不能标记整套完成。

### 6.3 轻量修改 P0

需求编号：PRD-07。

建议首轮评审从以下五项候选中，依据真实失败样本确定最终清单：抠图换背景、局部消除／重绘、尺寸裁切／扩图、清晰度增强、文案替换／本地化。此清单为本次建议，会议尚未确认具体工具。

交互统一为选择图片 → 输入说明或框选／标注区域 → 预览修改范围 → 查看增量费用 → 生成新版本 → 对照并选用。对话修改与标注引用同一目标图片和版本；用户未确认的修改不覆盖商品事实或当前交付版。文字修改能力不足时提示重生成或人工处理，不承诺复杂图层编辑。

保留原图、父版本及修改说明，可恢复选择旧版。单张重做只影响该图片；未受影响的成功结果保留。

### 6.4 批量任务 P0

需求编号：PRD-08。

提交前按 SKU 展示资料检查、适配模板和子任务数量。用户可跳过资料缺失项并提交其余项，跳过项不计为生成失败；取消或切换筛选不能悄悄扩大提交范围。

任务中心展示总进度、逐项状态、预计／实际费用及失败原因，支持刷新或重新登录后恢复状态。技术失败可只重试失败子任务；质量不满意使用“重新生成”，两者费用策略分别展示。

批次上限、并发数、单任务超时由模型与队列压测后配置，提交前明示；不得直接使用 ERP 的 2000 行导入上限作为生成批次上限。

## 7 视频试点

需求编号：PRD-09，优先级 P1。共用商品输入、任务与资产体系，效果验收独立于套图。

### 7.1 首批场景

| 场景 | 必需输入 | 用户确认步骤 | 验收重点 |
| --- | --- | --- | --- |
| 商品外观／卖点展示 | 商品与 SKU、适合镜头的参考素材、已确认卖点、市场和人群 | 风格 → 镜头及各自参考图 → 文案／字幕 → 成片参数和费用 | 外形、颜色、标识、规格和数量一致；不呈现无依据背面或功能 |
| 数字人口播 | 已确认讲解文案、人物／声音来源及可用授权、商品画面、语言 | 口播稿 → 人物／声音 → 商品画面搭配 → 费用 | 口播内容准确、音画及字幕可用；商品画面与人物表达分别检查 |

单张主图默认只能匹配已验证的有限运镜，不直接承诺多角度、开箱、涂抹、拆装及复杂人货互动。资料不足时提示补充、改用静态商品画面或调整镜头；调整方案后重新确认。

分镜卡包含时长、画面、参考图、文案、声音／字幕和限制。改动关键商品资料、参考或脚本后，该分镜确认失效。生成结果按成片及镜头关联商品；单镜头重做仅在工作流已支持时开放，不为试点建设完整时间线编辑器。

### 7.2 爆款复刻验证

将验证拆为两个方向，不能使用同一个“复刻成功率”：

| 方向 | 输入及验证要求 |
| --- | --- |
| 商品／人物替换 | 原视频、明确替换对象、可用参考与授权；检查替换范围、商品一致性、遮挡和交互；不支持镜头提前标明 |
| 脚本／分镜结构复用 | 参考视频、结构拆解、当前商品卖点；先确认新脚本分镜；验收结构与节奏可用及商品表达准确，不要求逐帧一致 |

混剪、翻译、首尾裁剪按真实需求另行评估第三方接入。视频分辨率、时长、音轨、帧率、格式及其计费单位在场景支持配置中明确，不能把当前 Demo 参数直接作为正式服务承诺。

## 8 资产沉淀与交付

### 8.1 自动关联与选用 P0

需求编号：PRD-10。

1. 结果文件成功转存且可访问后，自动关联输入商品和明确的 SKU，默认“待审核”；未选用也可追溯。生成时已引用的多商品组合保留组合关系，不能全部标成商品共用图。
2. 用户可调整关联商品／SKU。跨商品调整展示来源与目标并再次核对；保留原生成来源。只允许在同身份有权限范围内调整。
3. 结果关联不等于成为事实参考；“设为参考”和“人工选用”分别操作。素材文件、商品关联、套图归属分别保存，避免重复归档复制文件。
4. 过程产物如草稿文案、参考帧、失败中间图保存于创作记录，按需转为素材，不直接进入商品正式图集。
5. 一次套图包含用途槽位及其当前选用版本。新版本不覆盖历史文件；重新选用、撤回选用和交付均记录操作者及时间。

### 8.2 状态分离 P0

需求编号：PRD-11。

| 状态维度 | 状态示例 | 含义 |
| --- | --- | --- |
| 执行 | 草稿、排队、运行、部分成功、成功、失败、取消、结果待核实 | 只表达任务执行，不代表内容可交付 |
| 人工审核 | 待审核、需修改、已选用、已撤回 | 由有权限用户操作；兼容历史“已采用”为人工选用 |
| 生命周期 | 有效、已归档、已删除／失效 | 控制后续引用及访问，不覆盖历史事件 |
| 交付 | 未交付、已导出、回传中、ERP 已接收、回传失败、回传待核实 | 文件离开创作平台的状态 |
| 刊登 | 未知、待发布、平台成功、平台失败等外部回执 | 仅根据 ERP／平台真实记录更新，另存回执来源 |

“人工选用”“导出”“ERP 接收”“平台刊登成功”分别计量。没有接口回执时，刊登为未知；用户手工补记单独标明，不混入接口确认成功量。

### 8.3 导出与 ERP 回传 P0

需求编号：PRD-12。

导出支持单文件和所选套图包，包含按商品／SKU／渠道／语言／用途／版本命名的文件及清单。清单列明文件与 SKU、用途、顺序、版本及缺失项；保留适用的来源元数据。

ERP 回传由用户对选用版本发起，预览目标 ERP 商品、SKU、渠道、用途和顺序；默认追加为待选内容，不自动覆盖 ERP 主图或创建刊登任务。若业务要求替换，须有对应权限并确认新旧差异，具体写接口联调后开放。

回传保存交付 ID、所选资产版本、外部记录 ID、时间及回执。超时进入待核实状态，先查询结果；幂等重试不得重复追加。回传失败不重跑模型，ERP 已接收不标记刊登成功。

### 8.4 文件保留与权限 P0

需求编号：PRD-13。

商品档案、参考及已归档产物使用业务资产存储，必须与会话临时文件区分。现有会话文件保留规则仍适用于临时文件；用户存入商品时，在有效期内完成有权限的持久化转存，成功后才显示“已存入商品”。只保存会话文件链接不能算归档成功。

业务资产保留期限、容量与删除恢复策略需在试点前确定并在界面说明；未完成转存时提示失败／待处理。关联移除不直接删除被其他授权记录使用的文件；物理删除按存储和审计策略执行。

沿用现有多租户隔离需求：个人身份、企业 A、企业 B 分开；企业身份内的个人素材与企业共享素材分开授权。当前 Demo 的空间切换不作为生产鉴权依据。商品、资产、任务、快照、下载链接、计费账户与外部连接均固定身份；Web、API、MCP、Skill 每次操作检查权限。

## 9 任务服务与商业化

### 9.1 任务及接口 P0

需求编号：PRD-14。

四种入口调用同一任务体系：Web 负责引导；API 负责系统接入；MCP 提供边界清晰的场景工具；Skill 编排业务步骤。业务完整流程由业务方组装，内部协助 Skill 配置和接入的工作单列资源。

| 能力 | 必要契约 |
| --- | --- |
| 商品读取及创作检查 | 授权范围、商品／SKU、目标组合、缺失项、可用参考和支持状态 |
| 方案与费用预估 | 图片角色／视频分镜、模板／规则版本、计价单位、预计费用、有效期 |
| 创建任务 | 身份、业务线、调用来源、商品及 SKU、输入快照、方案、费用上限、客户端幂等键；返回任务 ID |
| 状态与结果查询 | 父／子任务状态、错误类型、可访问结果、资产 ID、实际费用及结算状态 |
| 取消／重试／重生成 | 目标任务及子项、操作类型、新尝试 ID、增量估价、原始任务关联 |
| 资产交付 | 资产版本、ERP 映射、交付幂等键、回执及查询方式 |

首期以创建、查询、取结果跑通异步闭环；回调能力按接入方需要追加。供应商未知状态不能当作明确失败再次调用；重启或页面关闭后可恢复查询。同一客户端幂等键和相同请求返回同一业务任务，请求内容变化返回冲突或要求新键。

### 9.2 费用与结算 P0

需求编号：PRD-15。以下为建议结算规则，须由成本及商业负责人在真实扣费前定版。

提交前展示模型／场景、数量或时长、计费单位、币种／积分口径、价格版本、预计消耗和用户授权上限。预估、内部模型成本、对客收入及内部结算分别记录，不能把模型成本当作收入。

| 情况 | 建议处理 |
| --- | --- |
| 预检查不通过／未进入执行 | 不扣生成费 |
| 排队中取消 | 释放预占额度；不扣未执行项 |
| 成功交付部分结果 | 按已公开规则结算成功子项，失败项释放或冲正 |
| 系统／模型技术失败 | 保留供应商成本记录；用户侧按定版失败策略不收或冲正 |
| 超时、供应商结果未知 | 标记费用待结算，先对账；不因用户点击重试重复扣费 |
| 用户因质量不满意主动重生成／修改 | 新建尝试，先展示增量费用；原结果保留 |
| 执行中取消 | 显示已发生／可能发生费用及最终对账状态，不承诺可撤回供应商调用 |

自动重试、模型切换均受用户授权上限约束，不能静默增加用户费用；需要提高上限时重新确认。每次尝试可记录模型成本，对用户同一业务交付只按定版规则结算一次。账单能追溯业务任务、尝试、供应商、价格版本、结算与冲正流水。

### 10.2 埋点与指标 P0

需求编号：PRD-16。

事件包括：商品导入／同步、预检查结果、方案确认、提交、子任务完成／失败、重试、重生成、修改、人工选用／撤回、设为参考、导出、ERP 回传及外部刊登回执、费用预占／结算／冲正。

事件关联身份、业务线、调用来源（Web／API／MCP／Skill）、商品／SKU、任务／尝试、资产版本、支持组合和价格版本。调用入口与业务线分开，同一业务任务跨入口查询不重复计算用量。

| 指标 | 建议定义 |
| --- | --- |
| 技术成功率 | 成功交付的输出子项数／已终态的执行子项数；取消、未知和仍运行项单列，明确统计窗口 |
| 套图完整率 | 必需槽位全部交付的套图数／已完成处理的套图数；技术完整与人工可用分别统计 |
| 人工选用率 | 指定生成批次在观察窗口内被选用的有效产物数／该批次成功产物数；按资产版本去重，撤回单列 |
| 导出与回传 | 分别统计导出、ERP 接收的资产／交付包，不视为实际刊登 |
| 刊登成功量 | 仅统计有 ERP／平台成功回执的记录；未知量单列 |
| 单位成本 | 供应商成本／成功输出量，及成本／人工选用量；图片和视频分别定义单位，分母为零显示不可计算 |
| 生成时长 | 排队、模型执行、转存及端到端耗时，报告中位数和 P95 |
| 内部覆盖率 | 接入的真实目标需求量／同业务线核实的需求量，单位、时间及来源一致 |
| 收入与结算 | 外部对客收入、内部结算、退款／冲正、供应商成本分别汇总；实际收入按财务口径确认 |

目标百分比、观察窗口、性能阈值由范围确认阶段设定，不把会议中不清晰数字当作验收线。下载、复制、归档等行为各自记录，不预先合并为采纳。

业务测算分别收集商城、1688、C 端刊登、营销的新增／存量商品、实际需要生成比例、每 SKU 图数／视频数、接入比例、技术成功率、人工可用率、单价和单位成本。输入按来源注明时间与单位。

会议中的约 5000 条／日是一次 TikTok 刊登统计，不是视频日产量；存量 SKU 数不等于付费生成量。200 万目标、约 60 万完成额、35 万视频分摊及 2000 付费用户均保留待统一的周期、币种、收入和人数口径；本月约 30 人、累计约 90 人不直接标为外部付费用户。800 万张×0.2 元为示例计算，不作为需求量或收入承诺。

## 11 质量验证与异常处理

### 11.1 质量验证

为每个支持组合准备真实商品样本，覆盖多 SKU、少图、复杂标签、尺寸缺失及跨品类情况。评测集与模板调优样本分开，失败案例按商品一致性、文案事实、规格、模板匹配、技术错误、输入不足分类。

首期优先规则和人工对照；检测模型、自动重试和模型微调先评估效果、成本与时延，再决定是否工程化。自动检查结果区分“通过”“不通过”“待人工确认”“无法检测”；没有检测不能显示为通过。

任何产物出现错误 SKU、颜色、结构、数量、尺寸文字或未经确认的事实，应标记需修改，不可作为专项验证通过样本。格式、清晰度及处理时长使用支持组合规定的目标；视频另检查声音、字幕和连续性。

### 11.2 关键异常

| 异常 | 用户看到的处理 |
| --- | --- |
| 素材失效／无权限 | 指明需补充或替换的引用；提交前再检查，不计为已完成输入 |
| 商品或参考更新 | 提示差异；未提交方案重新核对，已运行任务保留快照 |
| 暂无专项模板 | 标明通用试用或不支持，由用户选择，禁止静默套用无关品类 |
| 生成部分失败 | 展示成功与失败，保留成功项，可重试失败项 |
| 结果生成但转存失败 | 显示结果保存中／失败，优先补偿转存，不重新生成或重复结算 |
| 检测不可用 | 显示无法检测并提供人工核对，不视为自动审核通过 |
| 费用超限／额度不足 | 提交前阻断或暂停后续未执行项，展示已有结果及费用 |
| 外部回传超时 | 显示待核实，查询外部记录后再重试 |
| 权限撤回／退出企业 | 停止新的读取、下载、生成及交付；后台按权限和任务策略停止后续步骤并对账 |

涉及标签、证件和编号的争议生成不纳入已确认需求；不得凭图片编辑或生成声称商品获得认证或符合监管要求。原型及模板中的文字、链接、提示词属于业务输入，不授予工具执行或额外访问权限。
