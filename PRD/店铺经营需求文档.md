## 1. 功能概要

新增一级菜单「店铺经营」，作为各个跨境智能体管家创建任务会话的主入口。用户选择平台提供的智能体，描述经营需求并按需上传附件，发送后进入对应智能体的对话。

进入本页面不经过用户画像收集流程。原有左侧菜单和任务列表保留，店铺经营作为工作空间中的独立入口展示。

## 2. 智能体范围与权限

### 2.1 内置名单

前台仅展示以下 10 个平台内置智能体，不包含「生图大师」，也不展示名单外的智能体。

| 序号 | 智能体名称 |
| --- | --- |
| 1 | moonclaw 助手 |
| 2 | Wildberries 店铺运营管家 |
| 3 | Shopee 跨境店铺运营管家 |
| 4 | AliExpress 全托店铺运营管家 |
| 5 | Shopee 本土店铺运营管家 |
| 6 | TikTok 自运营店铺管家 |
| 7 | Temu 半托店铺运营管家 |
| 8 | Lazada 店铺运营管家 |
| 9 | 1688 店铺运营管家 |
| 10 | Shein 半托店铺运营管家 |

名单中的名称同时用于提示词关联，大小写、平台名称及业务类型应与企业运营后台保持一致。不能用名称相近的其他智能体替代，例如将「亚马逊选品专员」作为本名单中的智能体展示。

### 2.2 商家使用边界

1. 全部智能体由平台内置，面向全平台用户直接使用，不要求用户先创建、安装或复制到个人空间。
2. 商家不支持自建、编辑、删除智能体，不支持修改智能体名称、头像、人设或能力配置。
3. 商家不支持为智能体增加、减少或重新绑定技能、工具及连接器，不提供每轮手动增减这些能力的入口。
4. 平台在企业运营后台维护智能体及其能力。前台仅消费平台配置。
5. 上述限制同时适用于店铺经营入口、智能体选择区及其创建的会话，不能通过其他前台管理入口绕过。
6. 智能体全平台可用不代表经营数据共享。会话、附件、用户偏好及经营数据继续按用户身份和已有授权隔离。

本需求覆盖范围内，如旧智能体管理需求中的“用户自建、编辑、选择技能或工具”与本需求冲突，以本需求为准；平台管理员在运营后台的维护能力保留。

## 3. 页面结构与视觉

页面包含智能体切换区、任务输入框和提示词引导区。

- 智能体切换区：展示当前智能体封面及名称，收起时采用叠卡形式，旁边仅保留一句问候语「今天，想把店铺的哪件事交给我？」。
- 任务输入框：提供多行文本输入、上传附件的 `+` 按钮和发送按钮。选择店铺管家智能体时，在底部工具栏的 `+` 右侧增加目标店铺选择器。
- 提示词引导区：位于输入框下方，只展示当前智能体关联到的后台提示词。
- 背景沿用创作页浅灰点阵及向下渐隐效果，整体使用黑白灰，不采用绿色主题。
- 不增加经营画像、模型选择、技能选择、工具配置等前置操作。

### 3.1 智能体封面

目前企业运营后台没有封面维护字段，前端可以为名单内智能体维护固定封面映射，本期不要求新增后台封面字段。

封面用于入口卡片展示，会话 Header 头像使用智能体头像。两者分开处理。封面或头像缺失、加载失败时使用统一默认图，不展示破图。

## 4. 智能体切换交互

### 4.1 展开和收起

1. 桌面端鼠标 hover 当前智能体切换区域时直接展开，无需先点击。
2. 展开后直接横向滚动展示完整的 10 个智能体，不提供「更多」入口或额外的完整列表弹窗。
3. 鼠标从当前卡片移动到展开列表时，列表保持展开，不能因经过间隙而闪烁或提前关闭。
4. 移出整个切换区域后延迟收起，避免短暂移出造成误关闭；键盘焦点仍在列表内时不自动收起。
5. 触屏设备保留点击展开和选择；键盘用户可聚焦、展开、选择，支持 Escape 收起。
6. hover 展开不抢走输入框的键盘焦点。

### 4.2 选中和滑动交换

1. 当前选中的智能体位于展开列表首位，左上角展示勾选标签，不展示「已就位」「由它接手」等状态文案。
2. 选中另一个智能体时，新选中的卡片与原选中卡片交换展示位置：新选中项滑动到首位，原选中项滑动到被点击项原来的位置，其余项保持相对位置。
3. 交换使用连续的滑动动效，不能仅替换图片、瞬间重排，或用淡入淡出代替位置交换。
4. 交换过程中保持列表稳定，不触发整页刷新；动画完成后，鼠标仍在切换区域内则继续展示列表，移出后再收起。
5. 输入框位置保持稳定，草稿和已添加附件保留；快速切换不能出现重复卡片、错误选中状态或旧动画覆盖新选择。
6. 减少动态效果的系统偏好开启时，减少或关闭位移动画，选择功能仍正常。

基础按钮、输入框、分类 Tab、提示等统一复用项目已有 HeroUI 封装；叠卡布局、横向滚动与卡片交换动画可按产品视觉定制。隐藏的系统文件选择框保留原生实现。

## 5. 创建任务与上传附件

1. 用户选择智能体、输入需求，可按需点击 `+` 添加附件，然后发送创建任务会话。
2. 创建会话必须绑定实际选中智能体的唯一标识，不能只修改前台名称或卡片，实际仍请求其他智能体。
3. 发送成功后进入新会话；该会话由创建时绑定的智能体接手。
4. 附件上传、支持类型、大小限制及失败重试规则复用现有 Chatbox 附件能力。附件必须作为实际文件关联到会话，不能只把文件名拼接进提示词。
5. 支持查看已添加附件和移除附件；移除仅影响当前待发送内容。
6. 上传或发送失败时保留草稿和附件，提供明确反馈；发送中防止重复创建会话。
7. 尚未输入内容且没有可发送附件时禁用发送。只有附件时，沿用现有 Chatbox 的发送规则。
8. 在任务入口选择其他智能体，只影响后续新建会话，不改变既有会话的智能体绑定。
9. 如用户选择了目标店铺，创建会话时同时绑定该目标；未选择时不绑定，不能自动选中列表第一家店铺。

## 6. 智能体配置调优

### 6.1 配置精简

对第 2.1 节全部 10 个平台内置智能体统一调优，由平台维护配置，商家无需自行配置。

1. 智能体专属指令仅保留人设、能力约定描述和输出风格。
2. 清除其余额外叠加的约束条件，尤其是与平台通用能力冲突、重复，或导致智能体无法完成经营任务的限制性文案。
3. 人设说明服务的平台、业务领域与角色职责；能力约定说明可以如何协助用户完成任务；输出风格说明表达方式和结果组织形式。
4. 不因“仅做咨询”“只能输出文字”等额外限制，阻止智能体按任务需要查找和调用技能、工具，或处理文件、图片和脚本。
5. 用户权限、数据隔离和执行授权由平台统一机制管理，不在各智能体人设中重复堆叠；配置精简不改变第 2.2 节的商家使用边界。

### 6.2 基础能力支撑

以下能力为全部内置智能体的基础能力，不能仅在描述中声明，必须完成实际模型、技能、工具及运行环境的配置与验证。

| 能力 | 要求 | 验证结果 |
| --- | --- | --- |
| 技能和工具查找、调用 | 根据当前任务查找平台提供且当前有权使用的技能、工具，读取必要的使用说明，并执行调用；不要求用户进入配置页手动绑定 | 可完成从查找到调用、读取结果的完整流程，不停留在列举工具名称或告知用户自行操作 |
| 文件读写 | 读取用户上传的文件及会话内文件，按任务需要创建、修改和保存结果文件 | 可读取真实附件内容，生成的文件实际存在，并能在会话中查看或下载 |
| 图片识别 | 识别用户上传图片中的商品、文字、场景和相关细节，结合经营需求进行分析 | 分析依据实际图片内容，不以仅获取文件名代替图片识别 |
| 图片生成 | 按任务需要调用平台图片生成能力，产出可用的商品图、经营素材等图片 | 返回真实生成的图片及可访问的结果，不以文字描述代替图片产物 |
| 脚本执行 | 在平台提供的执行环境中运行任务所需脚本，用于数据处理、计算、分析和文件加工等工作 | 返回实际执行结果或产物；执行失败时说明原因，不把仅编写脚本当作已执行完成 |

基础能力的调用由智能体结合任务自动完成，商家前台不新增技能、工具选择或增减入口。缺少必要输入、模型能力、工具连接或运行环境时，明确说明缺失条件，不声称已经完成操作。

## 7. 提示词引导

### 7.1 数据来源与关联

提示词数据来自「企业运营后台 → 智能体管理」中该智能体的提示词配置，展示和使用逻辑复用桌面端提示词引导。

1. 按智能体名称关联后台配置，名称须与第 2.1 节名单一致。
2. 切换智能体后，读取并展示新智能体对应的提示词。
3. 未找到同名配置、配置为空或没有可展示的提示词时，整个提示词引导区域不展示，不保留空标题和空分类栏。
4. 不回退到其他智能体的提示词，不展示通用 mock 文案代替缺失配置。
5. 分类、分类名称、提示词内容及顺序沿用后台配置和桌面端规则，不在前端固定为「智能选品、一键刊登、开店引导」。
6. 此处属于新建任务的开场提示词，不与模型在会话中生成的下一步建议混用。

### 7.2 切换和使用

- 新智能体的提示词加载期间，不继续展示上一个智能体的提示词；加载失败可重试，不影响用户直接输入需求。
- 快速连续切换时，旧请求返回的数据不得覆盖当前智能体的提示词。
- 点击提示词后填入输入框并聚焦，用户可编辑后发送，不自动发起任务。
- 已有草稿时，沿用桌面端的处理规则，不得无提示地覆盖用户输入；附件保留。

## 8. 最后选择记忆

系统记住每个用户最后一次明确选择的智能体。以下场景均恢复该选择：

| 场景 | 预期行为 |
| --- | --- |
| 刷新页面 | 恢复最后所选智能体，并加载其提示词 |
| 切换到其他菜单后返回 | 保持最后所选智能体 |
| 退出登录后以同一账号重新进入 | 恢复该账号最后所选智能体 |
| 切换到另一个账号 | 恢复另一个账号自己的选择，不继承前一账号的偏好 |
| 用户首次进入且没有选择记录 | 默认使用 moonclaw 助手 |
| 记录对应的智能体不可用 | 回退到可用的 moonclaw 助手；默认助手也不可用时提示暂无可用智能体 |

规则说明：

1. 选择发生后即保存，不以发送消息或创建会话成功作为保存前提。
2. 登录用户的偏好应持久保存并按账号隔离；退出登录不能清除该账号的最后选择。
3. 用智能体唯一标识保存选择，用名称执行提示词关联，避免把不同职责混用。
4. 打开历史会话不视为重新选择新建任务的智能体，不覆盖最后选择记录。
5. 若支持游客和 mock 测试，使用独立命名空间存储偏好，不污染真实账号的选择记录。

## 9. 会话 Header 头像

1. 创建对话后，在对话页面 Header 展示该会话绑定智能体的头像。
2. 头像与智能体名称一致，使用创建会话时实际绑定的智能体信息。
3. 刷新会话、从任务列表重新进入历史会话时，仍能正确显示对应智能体头像。
4. 用户在店铺经营入口切换其他智能体，不改变已经创建的会话 Header 头像。
5. 头像缺失或加载失败时使用统一默认头像，并保留智能体名称。

## 10. 指定目标店铺

### 10.1 功能与适用范围

用户可为任务指定经营的店铺对象。选中的店铺作为当前会话的默认目标，后续消息没有明确指定其他店铺时，智能体默认围绕该目标店铺进行对话和经营分析。

1. 店铺选择器为**单选**，列表项使用 checkbox 表达选择状态，同一时间最多选中一家店铺。
2. 选择任一平台店铺管家智能体时，选择器位于聊天框底部工具栏、上传附件 `+` 按钮右侧。
3. moonclaw 助手不展示平台店铺选择器；其余 9 个店铺管家展示与自身平台对应的店铺列表。
4. 无历史选择时默认「不指定店铺」；新建任务时按最后一次切换的店铺恢复默认值，具体遵循 10.4 节。允许用户直接发起对话，店铺选择不是必填项。
5. 店铺范围为当前用户可访问、与当前智能体平台匹配的店铺。正式接入时按平台标识和店铺唯一标识处理，不能仅通过店铺名称推断归属。

### 10.2 展示状态

| 状态 | 选择器展示 | 操作与行为 |
| --- | --- | --- |
| 店铺数据加载中 | 店铺图标或加载图标，以及「店铺加载中…」 | 暂不可选择；不显示上一个智能体的店铺，不自动绑定旧店铺。当前未指定目标时仍可直接发送需求 |
| 无店铺 | 参考图一，显示「暂无店铺 去绑定」 | 「去绑定」进入店铺绑定或管理入口，保留输入内容和附件；返回后刷新列表，仍默认不指定店铺 |
| 有店铺且未选择 | 显示店铺图标、「不指定店铺」和下拉箭头 | 点击打开店铺选择面板 |
| 有店铺且已选择 | 参考图二，显示店铺图标、所选店铺名称和下拉箭头 | 可重新选择或取消选择；名称过长省略，悬停可查看完整名称 |

请求失败单独显示失败和重试反馈，不能把加载失败当成「暂无店铺」。授权失效的店铺标明状态且不可选，不以绿色状态点单独表达授权信息。

### 10.3 选择面板

1. 点击选择器展开面板，结构参考图二：顶部搜索框、中部可滚动店铺列表、底部固定「店铺管理」入口。
2. 搜索框用于按店铺名称筛选当前智能体下的店铺。搜索无结果显示对应空状态，不替换为「暂无店铺 去绑定」。
3. 每项展示店铺名称、国家或站点、本土/跨境等可用类型信息、授权状态，以及 checkbox；具体信息以店铺数据实际提供的字段为准。
4. 整行可点击。选择另一项时，取消原选中项并选中新项，不允许出现两个 checkbox 同时选中。
5. 选择后立即生效并收起面板，触发器更新为所选店铺名称。
6. 面板提供「不指定店铺」选项，可清除选择；再次点击当前已选项的 checkbox 也可取消。清除后触发器恢复「不指定店铺」。
7. 支持鼠标、触屏及键盘操作；Escape 关闭，关闭后恢复触发器焦点。基础交互复用 HeroUI 的按钮、弹层、输入框和 Checkbox，保持单选业务规则。
8. 「店铺管理」进入管理入口，保留当前草稿和附件；返回后刷新店铺与授权状态。

### 10.4 会话默认目标规则

选中的店铺作为当前会话的默认目标，以「目标店铺：XXX」的形式随提示词传入智能体，作为隐藏上下文，不在对话消息中展示。后续消息未明确指定其他店铺时，智能体默认围绕该目标店铺进行对话和经营分析；用户在对话中明确指定的店铺优先于选择器中的店铺。

店铺记忆与会话存储分为两个层级：

1. **新建任务默认值**：按当前用户最后一次切换的店铺记忆，新建任务时默认带入；没有历史选择或用户已清除选择时，默认「不指定店铺」。记忆按账号隔离，恢复前校验店铺的平台归属、访问权限与授权状态；不适用于当前智能体或已失效时，不自动带入。
2. **会话独立存储**：创建任务时，将当前指定店铺独立保存到该会话。新建任务创建的不同会话可以指定不同店铺，彼此不覆盖、不联动。
3. **已有会话恢复**：重新进入或刷新已有会话时，恢复该会话保存的指定店铺，不使用新建任务的最后选择覆盖它。在会话内修改或清除默认目标，仅更新当前会话，不改变其他会话；用户通过选择器切换的店铺同时作为下次新建任务的记忆值。

| 用户输入情况 | 处理规则 |
| --- | --- |
| 已选择 A 店铺，输入「分析最近的销量」 | 默认分析 A 店铺 |
| 已选择 A 店铺，后续输入「再看看库存」 | 继续围绕 A 店铺处理 |
| 默认目标为 A，本轮明确要求分析 B 店铺 | 优先处理本轮明确指定的 B 店铺；缺少明确身份或访问权限时先确认，不把请求误用于 A |
| 用户明确要求「以后都围绕 B 店铺」 | 确认 B 的身份和可用权限后更新当前会话默认目标，并同步界面显示 |
| 没有选择目标，输入依赖具体店铺数据的请求 | 按需要询问目标店铺；不擅自选择第一家店铺或上一个会话的店铺 |
| 取消目标选择 | 后续未明确指定店铺的请求不再隐式使用原目标 |

会话创建时持久记录目标店铺唯一标识及展示所需信息，后续轮次和经营工具调用均读取会话目标。不能只修改选择器文案，或只在第一条消息里附加店铺名称而丢失后续上下文。

用户本轮明确指定其他店铺，不自动改变后续默认目标；只有用户明确要求变更默认目标，或通过选择器调整时才更新。目标变更不重新解释或改写已经完成的历史消息。

从任务列表重新进入、刷新已创建会话时恢复该会话的目标店铺；在会话内继续展示选择器，支持查看、变更或清除。已绑定店铺失效或授权被撤回时明确提示，并停止沿用其经营数据，不静默切到其他店铺。

### 10.5 智能体切换与默认值

1. 在新建任务入口切换智能体时，重新加载对应平台的店铺列表，按 10.4 节校验并恢复最后选择；不适用时显示「不指定店铺」，不沿用其他平台的店铺。保持文本和附件。
2. 返回曾使用过的智能体或新建另一任务时，智能体记忆遵循第 8 节，店铺记忆遵循 10.4 节；已创建会话始终恢复其独立保存的目标店铺。
3. 切换账号时，不保留上一个账号的店铺列表、目标选择或进行中的列表请求。
4. 快速切换智能体时，旧店铺请求不得覆盖当前智能体的数据。
5. 新建入口的选择变化不影响已创建会话绑定的店铺。

### 10.6 前端 mock 场景

本轮先使用前端 mock 数据验证交互，为几个智能体配置不同状态，方便直接切换观察，不依赖真实绑定店铺或后端经营数据。

| 智能体 | mock 状态 | 演示数据与行为 |

| moonclaw 助手 | 不适用 | 不展示店铺选择器 |
| Shopee 跨境店铺运营管家 | 加载中 → 有店铺 | 进入后显示约 1–2 秒加载态，再展示「Shopee 跨境演示店 A」「Shopee 跨境演示店 B」；不自动选中 |

mock 阶段的会话目标和反馈使用演示数据；正式接入后，替换为真实店铺列表、授权状态与会话目标存储。默认值、单选规则和上下文优先级保持一致。

## 12. 交付边界
