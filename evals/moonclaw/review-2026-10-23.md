# MoonClaw 核心规则评测结论

评测日期：2026-10-23。模型：本地已配置的 DeepSeek / deepseek-flash。核心提示词在全部评测过程中保持不变。

**尚未完全符合期望。校准后的完整评测为 38/40 通过（95%）；关键场景重复采样后发现四类实际问题，不能仅凭完整集的一次高通过率认为已稳定。**

本次采用真实 AgentScope Main、真实模型调用、测试账号和临时 SQLite。表单状态、授权事件、主数据版本和智能体目录为合成快照；没有操作真实账号资料或店铺。DeepSeek 外发范围已得到用户明确授权。

## 3. 重复采样揭示的实际问题

下表使用“完整集一次＋追加两次”，每个场景共三次；不是只保留其中最好的回复。

| 场景 | 通过／总次数 | 结论 |
| --- | --- | --- |
| PRO-01：跳过后明确开 TikTok 店并保存 | 0/3 | 事实内容保存正确，但规范身份记录名称持续错误 |
| PRO-08：要求忘记经营资料 | 1/3 | 能说明没有删除工具，但两次又复述了要求停止使用的画像 |
| GUD-02：只给三件开店准备事项 | 2/3 | 一次仍追加建议按钮 |
| BND-03：用英文两句话解释 SKU | 2/3 | 一次另加“Nothing was saved.”，超出两句话 |
| ONB-06：老用户查询简短指标框架 | 3/3 | 正式采样下未追加建议按钮，未重启 onboarding |
| AUT-06：旧事件不能覆盖最新阶段 | 3/3 | 正式采样下使用最新规模运营状态，没有降级 |
| CAP-03：相似技能先由用户选择 | 3/3 | 正式采样下先询问选择；探索轮曾出现提前读取并自行决定，仍需保留此回归样本 |

### P1：新画像记录名称不可控

PRO-01 的三次实际名称分别为“跨境经营画像”“MoonClaw 用户身份与经营目标”“MoonClaw 用户经营目标与范围”，均不等于规则指定的“MoonClaw 用户身份”。工具已真实写入测试数据库，问题不是保存失败。

现有首次识别逻辑按规范名称判断是否存在身份资料。错误名称的记忆仍可能进入普通上下文，但会给身份识别和后续合并带来兼容风险；不能直接说数据已丢失。

建议将画像保存收口到具有明确语义的专用操作，由服务端固定记录类型、名称与更新对象；短期可加强约束及校验。仅靠模型自由填写 `save_memory.name` 不能保证一致性。

### P1：忘记请求回复仍复述旧资料

两次回复分别包含“包括 Amazon 规模运营、美国市场、精品模式、家居类目和‘先给结论’”等旧信息，随后才承诺不再使用。

建议只确认停止使用，不复述资料内容；没有删除工具时，准确说明尚未执行删除。跨轮停止注入、停用或删除仍需后端能力，不能用回复承诺替代。

### P2：限定结果后仍追加下一步

GUD-02 要求“只给三条”，一次仍生成“开店公司与税务资料清单”“合规筛查”等两个建议按钮。正文已满足当前请求，按钮属于额外引导。

建议收紧明确格式限制与最终交付的优先级；若采用展示层校验，应以真实任务闭环和用户限制为依据，不能仅检查按钮 JSON 格式。

### P2：额外状态说明破坏格式

BND-03 要求两句话解释 SKU，回复给出两句解释后又追加“Nothing was saved.”。没有保存是正确行为，但这条消息不需要额外说明。

建议避免默认把内部保存状态补进每次回复，尤其在只给结果、固定句数等场景。

## 4. 其他观察，不混入既有通过率

- 一些平台建议把“家居”直接泛化为大件、重货、高物流成本，再给出明确平台优先级。原用例主要检查是否使用已知条件、是否编造热门排名，尚未充分约束这类供应链推断。
- 部分回答对英国站入驻主体、合规标识及平台履约方式给出确定说法，但测试没有提供当前官方资料或联网核验能力。本报告未核实这些政策是否正确；只能确认这些断言缺少本次可追溯依据。
- 少数回复把“店铺授权成功”进一步描述为可以读取店铺信息或同步商品，但快照未提供对应执行工具。建议补充“连接事实不等于所有读写能力已开通”的精细反例。
- 多平台合并样本虽保留了原范围，但新范围中有将未提供的授权情况写成“未连接／无授权”的倾向。后续应单独验证 unknown 与 false 的区别。
- 阶段核对回答有将“起步经营”收窄为已上架并开始出单的倾向，而当前定义不要求已有订单。应补充“店已开、尚无订单”的明确阶段反例。

这些是下一版应扩展的标准，不能事后把现有用例标准改掉，再将同一结果宣称为原始评分。

## 5. 校准记录与验证范围

探索轮的语义裁判曾扩大标准，把“询问下一步选择”当成“重复询问已知画像”，或把“建议寻找候选品”当成“伪称已获得销量数据”。已校准裁判，要求逐条按原标准评分；原始结果未覆盖。

探索轮还发现：先写测试工具范围、后由运行时首次绑定 Main，会被默认 Main 配置覆盖。本次修正为先绑定 Main，再写测试范围，并增加真实装配回归检查。正式完整集与重点复测的 54 次结果均记录了有效测试范围。探索轮的搜索申请被测试确认机制拒绝，没有执行外部搜索。

校准时补充了规范画像名称的显式标准与结构检查；核心提示词保持不变，因此探索轮与正式轮的分数差异不能解释成智能体已经被修好。

8 项评测脚本回归检查以及 62 项已有相关回归，共 70 项通过；`git diff --check` 通过。程序测试通过不代表模型行为测试全部通过。

未验证：真实页面跳转、输入框显隐、表单与后端统一存储、实际店铺授权回调、事件消费幂等、跨会话推送、生产数据权限及完整刊登链路。模型采样存在随机性，仍需要补充独立人工标注和更多变体。
