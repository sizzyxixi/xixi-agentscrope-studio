# xixi agent studio 远程助理接入说明

在左下角账号入口进入个人中心，选择「远程助理」。钉钉和飞书可配置真实机器人，其他平台保留在「更多渠道」中展示，暂未接入。此页面仅展示第三方消息通道，不再展示网页控制台。

## 配置渠道

1. 在对应开放平台创建企业内部应用或企业自建应用，并启用机器人能力。
2. 在远程助理页面点击钉钉或飞书的「连接」，在居中弹窗中填写配置名称、已有智能体和当前账号的 LLM 模型。卡片和弹窗均有配置教程链接。
3. 填写应用凭证。「高级配置」默认收起，包含 Robot Code（钉钉）、额外 MCP、回复前缀和消息触发规则。额外 MCP 最多选择 3 个，并与所选智能体绑定的 MCP 合并生效。
4. 保存配置。保存不会建立连接；编辑 Secret 留空会保留已保存值，更换应用 ID 时需要重新填写对应 Secret。
5. 点击「校验凭证」，通过后点击「启用渠道」。观察连接状态，并完成平台权限、订阅、发布与应用可用范围配置。
6. 启用期间配置表单锁定；修改前先停用。停用后不再接收新任务，已运行任务仍可完成。重新连接不会删除历史会话。

### 钉钉

入口：[钉钉开发者平台](https://open-dev.dingtalk.com/)。使用企业内部应用的机器人，将消息接收方式设置为 Stream，并发布应用。填写 Client ID（AppKey）和 Client Secret（AppSecret）。

普通对话优先通过平台事件携带的临时回复地址回传。主动测试发送、或人工确认耗时导致回复地址过期时，需要配置 Robot Code，并赋予机器人单聊或群聊发送权限。未配置时，发送记录会标明失败，系统不会一直重试过期地址。

### 飞书

入口：[飞书开放平台](https://open.feishu.cn/app)。首期支持企业自建应用，需启用机器人和必要的消息权限，订阅接收消息事件，并设置应用可用范围及发布版本。

填写 App ID、App Secret 后，先在 xixi 启用本地连接，再到开放平台保存 WebSocket 长连接订阅方式。客户端需要能够访问飞书开放平台，不需要暴露本机的接收端口。参考[飞书官方长连接说明](https://open.feishu.cn/document/ukTMukTMukTM/uYDNxYjL2QTM24iN0EjN/event-subscription-configure-)。

飞书界面显示的“已连接”表示 SDK 长连接已建立；真实对话仍需要正确配置权限、订阅和发布。

## 授权发送者

新发送者默认没有调用模型和工具的权限。从平台向机器人发一条消息后，在「访问控制」中查看待授权申请，核对租户、发送者与会话标识，再选择允许或拒绝。未授权的消息正文不会保存到消息队列或发送给 LLM。

也可手动填写完整的租户、发送者和会话标识来添加允许项。授权绑定到具体身份和会话，不能使用通配符。允许的发送者可以调用此渠道绑定所选智能体的资料及工具，应只授权可信身份。

群聊默认需要 @机器人。不同群成员分别维护上下文。撤销授权后，该身份不能触发新任务，也不会接收尚未发送的结果。

## 对话与工具确认

首期支持文本。图片、文件、语音等消息会提示当前支持范围，不会假装解析附件。

支持以下命令：

| 命令 | 行为 |
| --- | --- |
| `/new` | 为当前身份开始新会话，保留旧历史 |
| `/stop` | 停止当前身份会话中的执行及排队任务 |
| `/help` | 展示使用说明 |

外部会话会出现在网页历史中，标题包含平台和配置名称。打开会话可查看内容、处理工具确认或停止运行；网页普通输入不会自动向外部发送消息。

需要写入类工具确认时，机器人会给出网页处理提示和会话编号。到网页确认后，执行结果会发送回原渠道。首期不支持平台内审批卡片，也不会把仅本机可访问的 localhost 链接当成手机可用入口。

## 测试与诊断

在「连接诊断」查看最近收发时间、消息处理状态和发送记录。

发送测试消息前填写明确接收目标，勾选内容与目标确认后再点击发送。飞书目标为机器人所在会话的 chat_id；钉钉私聊使用 Staff ID，群聊使用 openConversationId，并需 Robot Code 及发送权限。固定测试内容会在页面显示。

“已送达”表示平台确认接收请求，不能替代从平台发起对话的双向验证。对于网络中断或平台服务异常造成的发送结果不明，系统保留结果待核对，不自动重发或重新调用模型。

推荐在独立测试机器人中完成：授权身份发消息、机器人回复、继续上下文、群聊 @触发、网页工具确认、停用和断网重连。

## 本地运行与凭证保存

```bash
.venv/bin/pip install -r service/requirements.txt
npm run agent:dev
npm run dev
```

后台通过已安装的 `dingtalk-stream` 和 `lark-oapi` SDK 接收消息，每个机器人有独立接收进程。关闭 Python 服务或电脑休眠后无法实时收发；已启用渠道会在服务启动时尝试恢复连接。

Secret 使用 Fernet 加密保存在数据库中。可通过服务环境变量 `AGENTSCOPE_CHANNEL_KEY` 配置密钥；未配置时，在状态数据库目录自动生成权限为 0600 的 `channel.key`。默认位置为 `service/state/channel.key`，该目录已排除版本管理。迁移时需一并保存数据库和密钥；不要只复制数据库或随意更换密钥。

服务重启会将执行中和待确认的渠道任务标记中断，不自动重做可能产生写入的操作；发送结果不明的记录也不自动重发。

## 本次验证范围

已覆盖配置保存与脱敏、账号隔离、授权控制、事件去重、会话与执行配置隔离、命令、网页确认回传、发送失败处理、SDK 消息结构和前端交互。

开发与自动化测试使用独立数据库、测试数据及模拟 HTTP/SDK 输入，没有使用真实企业机器人凭证，也没有向真实会话发送消息。真实平台权限、机器人发布及收发联调需在配置有效凭证后完成。

会话技能选择入口为「新建任务」聊天框的「＋ → 技能」菜单，消息渠道配置不提供技能选择。
