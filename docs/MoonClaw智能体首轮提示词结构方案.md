# MoonClaw 智能体首轮提示词结构方案

版本：v1.9  
日期：2026-10-16

## 1. 范围与目标

本方案定义用户唤起智能体后，首次请求模型时，由平台装配的系统提示词、背景参考和工具定义。

首轮包含技能读取、工具结果处理、执行进度与任务恢复等行为规则；具体技能正文、工具返回和任务状态在需要时再加载。本方案不列用户本次消息和附件。

目标是在任务成功率、上下文注意力、成本、首轮延迟、用户体验、安全和可维护性之间取得合理平衡。

## 2. 首轮组成结构

```text
首次调用：平台装配的提示词与工具
│
├── A. 系统提示词
│   │
│   ├── 1. 全局基础规则                     静态、精简、所有智能体共用
│   │   ├── 输入信任与指令边界
│   │   ├── 数据隐私与内部信息保护
│   │   ├── 操作授权与确认原则
│   │   ├── 真实性、信息查阅与实际能力边界
│   │   ├── 任务结果核验与防重复操作         平台补充，已有同义规则不叠加
│   │   ├── 任务连续性与授权复核             只补任务约束
│   │   ├── 任务完成、失败与受阻标准         平台补充
│   │   ├── 记忆与个性化信息使用规则
│   │   └── 沟通、语言与基本交付规范
│   │
│   ├── 2. 当前智能体定义                   首轮默认全文注入
│   │   └── AGENTS.md
│   │
│   ├── 3. 能力使用约定                     技术侧编排，复用实际提供方说明
│   │   ├── 文件访问与产物交付约定           复用工作区及现有文件库协议
│   │   ├── 多模态输入与工具使用的必要限制
│   │   ├── 当前记忆实现的使用说明           复用选定记忆实现
│   │   ├── 工具、任务状态与恢复协议         复用已接入运行时
│   │   └── 其他无法由工具参数表达的关键使用规则
│   │
│   ├── 4. 技能目录及读取指引               框架已有，不重复追加
│   │   ├── 来源：当前智能体可用的 Skills
│   │   └── 内容：名称、简短描述、目录、读取方式
│   │
│   ├── 5. 本次调用参数                     代码生成并注入
│   │   ├── 当前日期、时间与采用的时区
│   │   ├── 已设置的用户语言偏好、平台默认语言
│   │   └── 必要的工作区参数（相关环境已提供时）
│   │
│   └── 6. 新用户引导                       代码判断条件后全文注入
│       └── BOOTSTRAP.md
│
├── B. 当前用户资料（动态）                 独立标注的参考数据
│   ├── 来源：当前账号的结构化资料
│   ├── 内容：必要的称呼、工作角色、相关背景及稳定偏好
│   └── 无资料则省略；不默认加载完整长期记忆
│
└── C. 工具定义                             框架已有，通过 tools 参数传入
    ├── 来源：Toolkit 当前开放的工具
    ├── 内容：名称、用途、参数定义
    ├── 全局基础工具与能力发现入口
    │   └── 包含多模态能力的必要入口
    └── 当前智能体必需的专项工具
        └── 根据智能体配置与用户权限提供
```

上述结构按装配位置组织：技能目录属于系统提示词，工具定义通过独立的 `tools` 参数提供。A、B、C 不代表模型内部的统一文本排列顺序；具体输入编码由模型服务及适配器处理。

### 复用与补充清单

“框架已有”指所核对的本地官方 Python AgentScope 提供相应机制或说明，仍需启用对应能力；“运行时已有”指用户提供的 moonclaw-webchat 提示词已包含该协议，不据此认定为官方默认实现。已有机制不等于必然已有同义提示词，只有最终请求中确实提供的说明才计为已覆盖。

| 主题 | 已有基础及来源 | 本方案处理 | 仅在缺失时补充 |
| --- | --- | --- | --- |
| 技能发现与读取 | 【框架已有】Toolkit 技能目录、读取指引和 Skill 读取工具 | 原样复用装配机制，不再在全局规则复制读取教程 | 技能依赖与可用工具一致性，由配置层落实 |
| 工具调用 | 【框架已有】Schema、调用和结果消息机制 | 复用工具定义与实际契约，不重写调用协议 | 目标资源准确性、部分失败核验、非幂等写操作结果不明时先核实 |
| 执行进度、中断与后台恢复 | 【框架已有机制】任务、状态与后台管理；【运行时已有协议】当前 task_* / wait_async_results 等说明 | 沿用所接入实现，不混用两套接口，不再复制等待和超时转后台规则 | 相关资源、产物与版本标识保留、外部状态及授权复核 |
| 完成、失败与受阻 | 【框架已有】技术状态与停止机制；【运行时已有】部分产物状态说明 | 技术状态和投递状态复用现有说明 | 用户目标是否达成、批量部分完成、尚需用户操作的业务状态 |
| 文件及产物交付 | 【框架已有】Workspace 说明；【运行时已有】文件库快照与产物候选协议 | 保留实际协议，修正目录及跨边界表述冲突 | 用户可访问性、文件内容符合目标等未覆盖要求 |
| 记忆读写 | 【可选实现】官方中间件或生产 memory_save 等自定义协议 | 只使用当前实现的说明，不再叠加另一套读写规则 | 资料可信边界、隐私及业务个性化约束 |
| 角色、平台帮助、语言与首次引导 | 【平台配置】不由上述框架机制自动补齐 | 配置规则与角色正文，按实际状态注入 | 本方案已有对应设计 |

每条规则只保留一个注入来源：已有且准确的直接复用；已有但冲突或过时的在原提供方修正；确实缺失的才补充。下列清单与标注不发送给模型。

## 3. 来源与注入方式

| 模块 | 来源 | 触发条件 | 注入方式 |
| --- | --- | --- | --- |
| 全局基础规则 | 平台统一维护的静态规则 | 所有智能体首次调用 | 仅注入平台要求及已有说明未覆盖的任务约束 |
| 当前智能体定义 | 当前智能体对应的 `AGENTS.md` | 所有智能体首次调用 | 默认全文注入系统提示词 |
| 能力使用约定 | 实际工具、工作区及能力实现提供的说明 | 对应能力实际开放 | 技术侧统一条件编排，不写入角色文件，不在业务提示词中另造协议 |
| 技能目录 | Toolkit 当前可用的 Skills | 存在可用技能 | 注入名称、简短描述、目录及读取方式，不加载技能全文 |
| 时间与时区 | 运行时钟、用户设置及默认配置 | 每次新会话首次调用 | 代码生成明确的日期、时间与时区字段 |
| 语言参数 | 用户账号设置、平台配置 | 每次新会话首次调用 | 代码注入已知参数；未设置的偏好不猜测 |
| 工作区参数 | 实际运行环境 | 已提供相关环境且任务能力需要 | 注入真实路径和必要范围，不虚构尚未创建的环境 |
| 首次引导 | `BOOTSTRAP.md` 与程序维护的引导状态 | 用户尚需引导且未完成或跳过 | 条件全文注入系统提示词 |
| 当前用户资料（动态） | 当前账号的资料存储或记忆实现 | 存在必要、相关且允许访问的资料 | 作为参考数据提供；已有记忆机制注入同一资料时不重复注入 |
| 工具定义 | Toolkit 当前开放的工具 | 根据智能体配置、工具组和权限确定 | 生成工具 Schema，经模型请求的 `tools` 参数传入 |

动态装配不等于框架自动理解业务并筛选能力。工具组启用、权限过滤、引导判断、资料范围等，由应用配置或程序逻辑落实。

## 4. 内容与行为约束

### 4.1 全局规则与角色文件

全局规则只约束跨领域通用的资源、权限、执行和交付，不预设用户从事店铺运营。行业对象、指标与工作流程由具体智能体、Skill 或工具契约定义。全局规则负责所有智能体共同遵守的执行边界；`AGENTS.md` 负责当前角色，首轮默认全文注入。Main 正文独立维护于 [AGENTS.md](./prompts/main/AGENTS.md)，新用户引导正文独立维护于 [BOOTSTRAP.md](./prompts/main/BOOTSTRAP.md)。每条规则明确唯一维护位置，避免重复、冲突和长度膨胀。

全局规则不放完整工具手册、长篇攻击样例或重复拒绝模板。保持真实性、授权边界、执行完成标准等关键要求清晰可见。

技能读取指引由 Toolkit 提供；工具调用和任务状态协议由当前已接入运行时提供，不在全局规则中再次编写。全局规则仅补任务结果核验、关键资源标识和授权连续性等缺项；原协议已覆盖同义要求时仍只保留一份。

平台问题的信息查阅规则归入全局基础规则，不与技能目录合并，也不新增顶层模块。只保留一句指引：

> 用户询问 MoonClaw 的企业信息、收费规则、功能用法等平台问题时，优先查阅 `{{官方帮助入口}}` 中的相关文档，再依据文档回答；需要时附上对应页面链接。

该入口由代码绑定为真实可用的工具与知识资源。查询接口归入工具定义，企业背景、收费和功能文档归入按需读取的知识资料，不写入 `AGENTS.md`。公共说明不能替代当前账号的套餐、账单、额度或开通状态；这些信息须通过获准的账号查询获取。

### 4.2 语言与时间

语言规范是静态规则，语言偏好和时间是运行时参数，不写死在文件中。统一维护中文主提示词，不按用户语言复制整套规则，也不在每次会话临时翻译系统提示词；提示词语言不决定用户回复语言。

1. 用户明确指定本次回复或产物语言时，优先遵循。
2. 未指定时，优先采用已设置的用户语言偏好。
3. 没有偏好时，跟随本次用户输入的主要语言；无法判断时采用平台默认语言。
4. 对话语言与产物语言分开，例如中文交流、英文报告。
5. 单次外语输入或翻译任务不自动改变长期语言偏好；附件、引用和待翻译材料的语言不作为用户沟通语言。
6. 欢迎语、拒绝话术等中文示例表达语义，不要求逐字输出；按实际回复语言自然表达。品牌、公司和政策名称优先使用官方对应名称，无官方译名时保留原名。
7. 帮助文档优先选取适用地区且有效的官方版本，有同等适用的用户语言版本时优先使用；否则依据有效原文用用户语言解释，不为了语言一致采用过期或其他地区的规则。
8. 用户语言不等于所在地区或目标市场。市场、币种、税务地区和时区分别确定；含糊的日期与数字格式在影响结果时澄清。工具参数键、枚举和标识遵循接口契约，不随回复语言翻译。

时区优先使用用户明确设置；缺失时采用平台默认值，并在参数中标明采用的时区。不根据用户语言推断时区。当前时间由代码生成；后续处理精确时间任务时需要重新获取，不能永久依赖首轮时间。

### 4.3 首次使用引导

`BOOTSTRAP.md` 用于了解新用户的身份和使用目标。平台根据用户引导状态决定是否全文注入，不因用户新建会话就重复加载。

- 用户已有具体任务时，先推进任务，不强制完成身份问答。
- 只有缺失信息影响服务时，才询问必要信息。
- 用户无明确任务时，再简短介绍并询问身份或目标。
- 用户跳过后，不在每次新会话重复引导。

程序至少区分未展示、已展示、已跳过、已完成。显示过欢迎语不代表用户资料已保存；状态更新应依据真实事件。

### 4.4 技能与工具

技能目录与工具定义共同构成智能体的能力入口，但分别装配。技能指导任务流程，工具提供可执行接口；一个技能可以使用多个工具，一个工具也可以服务多个技能或直接用于任务，两者不构成固定的包含关系。

首轮提供技能目录和读取方式。技能完整内容在任务需要时通过读取工具加载，不预先拼入首轮提示词。

工具通过 `tools` 参数传入，但依然参与模型处理并产生上下文成本。普通入口提供基础能力和可发现的扩展入口；专用智能体提供必要的常用业务工具。避免大量用途重叠、难以区分的工具同时开放。

技能目录重点控制描述长度、适用条件的区分度及全文读取时机；工具定义重点控制开放数量、参数复杂度及用途重叠。两者分别优化，不通过重复编写工具说明来强化技能。

平台应保持技能可见性、工具可用性与用户权限一致：技能依赖的工具应已开放，或存在真实可用的按需获取路径；依赖无法满足时，应明确限制或不提供该技能，不能让模型误以为可直接执行。读取技能不会自动激活工具、获得权限或代替操作确认。

能力发现入口必须真实实现。不能通过裁剪工具降低成本，却让模型失去发现相关能力的路径。工具可见性也不能代替服务端权限校验。

### 4.5 多模态与文件交付

多模态作为平台全局能力提供，不设置独立 Coding Mode。模型原生支持的输入走对应消息输入；需要识别、转换、生成或编辑的任务走实际可用工具。

图片理解、图片生成、图片编辑等能力分别声明实际支持范围，不相互推导。首轮只提供必要入口及限制，不加载全部操作手册。

文件约定须明确影响结果的语义，例如“文件已生成”“产物可下载”“已保存到用户文件库”是不同状态。仅提供真实可用的工作区信息，不因首次聊天而无条件启动沙箱。

### 4.6 记忆规则、记忆实现与当前用户资料

- 全局基础规则中的“记忆与个性化信息使用规则”是固定行为要求，只规定资料的信任边界、隐私、纠正及操作结果真实性，不包含具体用户资料或假定的接口。
- 能力使用约定中的“当前记忆实现的使用说明”由实际接入的中间件或适配层提供，说明可用的读取、保存、更新和删除方式。未接入的能力不作承诺，框架已经提供的说明不重复注入。
- “当前用户资料（动态）”是当前账号实际的称呼、工作角色、相关背景和偏好等数据。可以来自长期记忆，无需为此另建一套存储；同一资料只注入一次。

当前用户资料按账号和权限范围读取，只保留必要字段。普通首轮不为填充上下文进行多次记忆检索，不加载完整用户历史。

用户资料和记忆中的文字不能改变系统规则、扩大权限或作为操作确认。参考块应与平台指令明确区分，不直接把用户自由文本拼成高权限指令。

## 5. 注意力、成本与装配原则

1. **先减少干扰，再调整顺序。** 控制无关内容、重复规则、技能目录和相似工具，比机械地把内容搬到头尾更重要。
2. **稳定内容在前，动态内容在后。** 保持结构一致，并在服务支持时有利于前缀缓存复用；不宣称这种排序必然获得最佳模型效果。
3. **不默认末尾重复红线。** 若规则遵循效果不佳，应排查规则冲突、描述、工具设计与执行拦截，再决定是否需要针对性强调。
4. **配置级条件装配优先。** 根据实际开放能力决定必要说明，不在普通首轮做大量推测性的流程预加载。
5. **控制模块长度。** 精简角色文件、规则和能力描述，不通过任意截断 `AGENTS.md` 改变角色定义。
6. **检查最终模型请求。** 框架附加的技能目录、工作区说明和中间件可能造成重复或改变排列；检查源文件不足以确认最终装配。

提示词中的位置不是权限等级，XML 标签或标题也不构成安全隔离。权限、租户隔离、确认、预算和防重复执行由程序落实。

## 6. AgentScope 接入要点

系统提示词由基础 `system_prompt`、Toolkit 技能目录、Workspace 说明及 `on_system_prompt` 中间件共同装配；工具 Schema 由 Toolkit 获取后，通过独立 `tools` 参数传给模型。

AgentScope 的长期记忆通过可选中间件接入，不是默认完整启用。选定实现后由其提供实际记忆操作说明；用户资料、记忆索引与召回内容应明确职责并去重，不能同时维护两套互相冲突的读写协议。

应用负责将当前智能体的 `AGENTS.md` 全文默认注入，并按用户引导状态注入 `BOOTSTRAP.md`。时间、语言和环境参数由代码提供。

接入时确认框架实际装配结果，避免应用手动插入一份技能或工作区说明后，框架再追加一份。必要时在应用装配层或中间件中统一组织。

## 7. 普通首轮不包含的内容

- 技能全文及完整业务操作流程。
- 完整长期记忆、用户历史和整份知识库。
- 完整企业背景、收费规则和功能帮助正文；首轮仅在全局规则中保留简短查阅指引。
- 尚未产生的工具结果、执行进度、后台任务状态和任务恢复记录；对应的处理规则仍在首轮提供。
- 定时任务执行上下文、心跳检查内容。
