# 对话创建定时任务

## 目标

用户通过自然语言描述未来或周期任务，在会话中核对任务卡片并确认创建，无需跳转填写表单。所有普通对话智能体共享此能力，任务执行仍遵守当前智能体配置和账号权限。

## 触发与澄清

| 用户表达 | 行为 |
| --- | --- |
| “明天上午九点整理销售日报”“每周一、三九点检查库存” | 识别为创建意图，收集完整参数，准备确认卡片 |
| “提醒我处理一下”“以后定期看看” | 询问具体时间/频率及要做的事情，不猜测、不创建 |
| “每天九点”但上午/下午或任务内容不明 | 合并询问缺项，避免多轮逐字段盘问 |
| “现在分析报表”“定时任务怎么用”“举一个定时执行的例子” | 正常回答/执行，不生成调度任务 |
| 卡片后说“改成十点” | 先取消当前确认，再按新要求生成卡片，旧卡片失效 |
| 自动化运行会话或渠道会话 | 不挂载创建工具；引导在普通对话创建，避免自动任务自我复制 |

相对时间按每轮服务端当前时间解析；默认时区 Asia/Shanghai，卡片显式展示，可按用户要求使用其他 IANA 时区。过去的单次时间不可提交。周一对应 weekday=0，每周/双周必须指定星期，每月必须指定日期，每年必须指定月日。

## 对话与确认流程

1. 理解任务，补齐内容、时间及频率。存在类似技能候选时沿用全局策略让用户选择。
2. 调用只读 `prepare_scheduled_task`：复用现有服务校验，计算首次有效执行时间；不产生定时任务或运行记录。
3. 调用 `create_scheduled_task(draft_id)`：由 AgentScope 原生写入确认点暂停执行；前端渲染结构化卡片。
4. 点击“确认创建”后，服务端再次校验权限、资源启用状态、时间及重名，再保存。文字“确认”不替代按钮授权。
5. 保存成功显示“已创建”，任务进入自动化列表，执行结果在独立运行会话和运行记录查看。失败保留清晰原因，不声称已成功。

每张确认卡片只创建一个任务，不与其他写操作混合确认。多任务按顺序分别核对。用户可点“取消 / 修改”，再直接描述修改要求；不需要学习 cron 表达式。

若模型误将创建任务与其他调用合并确认，服务端拒绝整批执行并要求分别发起，不扩大用户在单张卡片上的授权。

## 确认卡片

```text
⏰ 定时任务                              待确认
销售日报
汇总昨天销售额并列出异常商品。

执行规则    每周 · 周一、周三 · 09:00
首次执行    2026/10/26 09:00 · Asia/Shanghai
有效期      长期有效
智能体      当前会话智能体
模型        当前模型（未固定时为账号默认模型）
指定能力与店铺  仅在显式绑定时显示真实资源名称
结果位置    自动化 → 运行记录

                      [取消 / 修改] [确认创建]
```

卡片直接呈现在会话正文区域，不折叠到执行过程里；已保存的卡片随消息历史保留。界面中英文随偏好切换，用户输入不翻译。按钮使用 HeroUI，不新增确认弹窗。超过长度的提示词可滚动阅读，窄屏自动换行。

## 调度执行规则

- 支持现有单次、每小时、间隔 1–24 小时、每日、每周、每双周、每月、每年及有效期。
- 复用现有时区与日历计算：不存在的日期跳过；2 月 29 日只在闰年执行；DST 不存在的本地钟点跳过。
- 不主动补跑全部错过的周期；沿用调度器现有到期领取和后续时间计算。后台运行以独立会话记录，不继续占用当前会话，也不承诺系统推送、短信或站外通知。
- 沿用当前会话智能体与模型，不接受模型通过 config 改成其他智能体。技能/MCP各最多显式指定3个，未指定的能力受智能体配置控制。执行时再次验证资源可用性。
- 当前持久服务每5秒检查到期任务。**当前 Serverless 模式不启动调度器**，卡片必须提示“当前部署未启用自动调度，保存任务后不会自动执行”。本需求不把创建入口误报为已解决生产调度基础设施；生产定时执行发布仍需常驻调度服务或受保护的外部触发器。

## 安全和异常

- 草稿绑定账号及会话，由服务端生成；确认时不接受前端篡改任务内容。草稿15分钟有效，新草稿替换旧草稿。
- 重复提交同一草稿通过现有 request_id 幂等机制返回同一任务，不重复创建。
- 资源停用、删除、权限变化、模型删除、重名或单次时间已过，确认失败并要求重新准备。
- 关闭页面不会自动确认。进程重启/切换实例导致原生确认点丢失时，提示重新发起；不自动恢复写入或替用户点击确认。草稿持久化和跨实例恢复为后续增强。
- 账号隔离、店铺授权、智能体白名单不能被自然语言绕过。创建调度属于全局平台管理能力，不能借此增加任务智能体的执行能力。

## 用户体验自评

| 维度 | 分数 / 10 | 判断 |
| --- | --- | --- |
| 操作成本 | 9 | 一句话 + 一次确认；只询问缺项 |
| 可理解性 | 9 | 展示真实首跑时间和时区，不暴露 cron/JSON |
| 可控性 | 9 | 未确认不保存；取消、修改及失败有明确反馈 |
| 反馈可信度 | 9 | 区分保存与自动执行，明确结果入口 |
| 编辑与恢复 | 8 | 修改需先取消；重启后需重新确认 |

平均 **8.8/10**，达到本地落地标准（≥8）；生产自动执行需单独通过调度服务部署验收。改进重点是后续支持卡片直接编辑和确认点持久恢复，不以增加首期配置复杂度换取覆盖率。

## 验收与测试范围

- 草稿预检不落库；真实确认保存一个任务；同草稿重复提交仍为同一条。
- 过期/被替换草稿、跨账号、越权资源、已停用资源、越过白名单、过去单次时间均失败。
- 全部普通对话智能体有创建入口；运行/渠道会话没有；写工具始终要求原生用户确认。
- 原生确认事件生成包含服务端快照的消息卡片，保存历史后仍可显示；取消不产生任务。
- 校验卡片中英文、首跑时间/频率/时区/状态及主要交互；进行 TypeScript、限定文件 Lint 和相关调度回归，不重复运行无关全套测试。
