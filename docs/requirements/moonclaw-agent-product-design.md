# MoonClaw 跨境卖家助手：Agent 设计与全流程需求

- 版本：v1.0 整合评审稿
- 日期：2026-10-23
- 适用对象：产品、设计、前后端、Agent 开发、测试与运营。
- 范围：智能体工作台分流、首次引导、持续画像、个性化首页、专业智能体协作、商品管理、刊登、连接器及变化反馈。
- 本文统一整理业务目标与设计；字段、服务和状态机标为“目标设计”的部分尚未全部实现，不能作为当前生产能力承诺。

## 1. 产品定位与关键结论

MoonClaw 是平台默认通用助手，也是跨境卖家的经营参谋和平台使用引导助手。用户可以直接完成翻译、写作、文件、调研和分析任务；进入跨境经营场景后，再结合经营范围、商品来源和真实能力推进业务。

| 设计决策 | 统一口径 |
| --- | --- |
| 智能体与工作台 | 新建任务时按所选智能体决定工作台，MoonClaw 的卖家引导不覆盖其他智能体 |
| 首次体验 | 显示独立画像收集面板，隐藏聊天输入框；不在同屏混排模拟对话 |
| 经营阶段 | 采用“筹备开店、起步经营、规模运营”；起步经营解释为“已开店，正在小规模试水”，不要求已有订单。属于本稿统一推荐文案，界面与存量枚举需一并对齐 |
| 其他／随便看看 | 作为跳过动作，直接创建独立会话；不作为长期经营阶段，也不认定用户是新手 |
| 表单和对话 | 两者都是画像来源，具体任务优先，信息渐进补全，不要求先交齐画像才能使用助手 |
| 画像范围 | 一个账号可有多个平台／市场经营范围，不用一个全局阶段覆盖所有业务 |
| 存储 | 目标采用数据库主数据；每用户 USER.md 为只读投影。共享 user.md 只定义规则 |
| 推荐与执行 | 只推荐可信目录中实际可用的智能体；连接成功不等于具备全部读写能力 |
| 当前交付 | 前端交互 Demo、核心规则、文本画像保存适配及评测已有；真实业务连接与统一结构化画像仍待接入 |

## 2. 全流程与页面动线

### 2.1 总体入口

1. 用户新建任务，选择智能体。
2. 非 MoonClaw 使用该智能体自己的工作台与角色规则。
3. MoonClaw 查询账号引导状态及有效画像：首次未收集进入面板；已有画像进入个性化首页；已跳过则允许直接进入会话，不反复强迫收集。
4. 面板确认后保存画像，刷新匹配能力，进入个性化首页。
5. 点击“其他／随便看看”“帮我看看怎么选”、专业智能体或首页对话入口，均创建独立会话过程页；首页不内嵌模拟聊天区域。
6. 后续表单修改、明确对话事实和可信系统事件更新同一账号画像，并刷新首页及会话上下文。

“有账号引导标记”“画像完整”“店铺授权”是独立判断，不可直接互相推导。上面是目标产品动线；当前后端首次标记仍为简化实现，见第 12 节。

### 2.2 首次收集面板

| 选择 | 收集字段 | 交互要求 | 完成后的起点 |
| --- | --- | --- | --- |
| 筹备开店 | 目标平台多选、目标市场、目标经营类型 | 平台可配置热门标签；提供“还不确定”及“帮我看看应该怎么选” | 平台选择、开店准备、货源与选品验证 |
| 起步经营 | 经营平台多选、市场、经营类型、主营类目 | 解释为已开店、小规模试水；不追问订单来证明阶段 | 首批商品、刊登准备、动销与基础经营 |
| 规模运营 | 经营平台多选、市场、经营类型、主营类目 | 不在首屏强制收集 GMV、团队规模和所有系统 | 经营诊断、批量协作、效率优化 |
| 其他／随便看看 | 不强制填写 | 保存跳过意愿，直接新建会话，不进入第二步表单 | 正常通用对话，后续按需补全 |

目标设计中前三类提交时校验上述适用字段；选“还不确定”是有效回答，不等于漏填。尚不具备完整资料的用户始终可以跳过或进入咨询。取消修改不覆盖原正式画像。

平台候选范围：TikTok Shop、Temu、Wildberries、Ozon、Yandex、Shopee、Lazada、1688、速卖通、SHEIN、美客多、Amazon、Shopify、Joom、Qoo10、amag。amag 保留原始提法，正式名称和范围待确认。画像可选择某平台，不代表已有该平台的连接器、专家或刊登服务。

热门标签由运营配置来源、适用市场与更新时间，不由模型凭印象生成实时榜单。经营类型提供精品、精铺、铺货、还不确定，并给简短解释；不把类目或类型直接等同商品重量、预算、客单价和物流条件。

### 2.3 选择咨询与返回补全

点击“帮我看看应该怎么选”时，携带已选字段、缺失项、来源及草稿 ID 创建独立会话。Agent 只帮助当前选择，已有平台或市场不重复询问。模型建议作为候选，由用户采纳后通过统一画像服务保存；返回面板时恢复草稿，不自动把建议写成确定事实。

### 2.4 个性化首页

参考现有 MasterGo 设计，保持欢迎／引导横幅、主输入区、快捷功能、专业智能体卡片、案例等结构，按画像和实际能力改变内容与优先级。

| 区域 | 需求 | 降级处理 |
| --- | --- | --- |
| 欢迎与阶段引导 | 承接当前经营范围和最近可信变化 | 缺画像时给通用起点，不假定用户平台 |
| 主输入区 | 可直接提出任务；进入正常会话过程页 | 没有完整画像也可使用 |
| 核心快捷功能 | 刊登、选品、经营分析；扩展内容创作、市场调研、客户运营等 | 缺能力时显示准备材料、配置连接或咨询路径 |
| 专业智能体 | 按所选经营平台匹配真实目录，展示名称、用途、匹配原因及对话入口 | 无匹配专家时使用通用助手，不编造专家或会话链接 |
| 成功案例与商机 | 案例带来源、适用平台／市场及条件；商机作为探索建议 | 没有真实内容时空态，不虚构成功数据或收益保证 |
| 修改资料 | 可调整当前经营范围，确认后刷新推荐 | 取消保留旧值；冲突先核对 |

多平台用户应能选择当前经营范围，或分组展示推荐；不能因为最近说准备 TikTok 店，就把已有 Amazon 规模运营的首页整体降级。

## 4. 商品管理与刊登完整流程

### 4.1 商品管理

提供商品池，支持新增、编辑、搜索、按平台或类目筛选、导入表格、查看变体及选择商品刊登。目标模型区分 SPU 商品和 SKU 变体；Demo 的单行 SKU 不应被视为最终商品模型。

导入流程：选择文件 → 预览与字段映射 → 检查必填和数值 → 识别重复 SKU → 展示逐行错误 → 用户确认处理规则 → 分批入库。重复记录采用新建、跳过或更新的策略需用户明确，错误行可修正重试，不能一行错误丢失整批已校验数据。

### 4.2 刊登入口与商品来源

| 来源 | 操作 | 关键规则 |
| --- | --- | --- |
| 平台商品池 | 多选商品及具体 SKU | 保留选择；核对资料与库存来源 |
| 西之月 SKU／链接 | 输入、查询、核对规格 | 仅真实接口成功才展示真实价格库存 |
| 外部商品链接 | 输入、解析、确认 SKU | 解析失败允许更换或手工补充，不丢失目标店铺配置 |
| 外部商品系统 | 先询问维护位置，再选连接／导入 | 不限领星；店小秘等系统以实际连接目录为准 |

未连接外部系统时，进入“能力市场 → 连接器”配置对应 ERP 项目，或通过“如何连接我的某 ERP 商品进来刊登”创建独立咨询会话。不能假设任意连接器都已支持，不能编造授权链接。返回时恢复来源、SKU、目标店铺和已填配置。

### 4.3 目标店铺与授权

1. 没有可用店铺：展示当前实际支持连接的平台，可进入授权；同时允许先准备商品资料与文本草稿。
2. 有店铺：一级展示平台及店铺类型，例如适用平台中的本土店、跨境店、半托管；二级选具体店铺并显示站点、类型和连接状态。
3. 真实发布前核对当前账号权限、店铺有效授权、目标站点和 SKU 范围。
4. 已连接只证明连接事实。库存查询、商品同步、发布仍需相应工具和权限；连接器授权和电商目标店铺授权分别维护。

### 4.4 配置、确认与执行

| 层次 | 内容 | 规则 |
| --- | --- | --- |
| 基础商品主数据 | 名称、规格、图片、材质、重量、成本等 | 唯一来源，不因店铺标题价格差异复制基础 SKU |
| 批次默认配置 | 当前批次统一的发布方式、价格规则、库存、物流等 | 未使用批次时可跳过；不能冲掉已明确的例外 |
| 店铺／SKU 覆盖 | 本店标题、价格、数量、属性或特殊要求 | 优先于批次默认；不自动反写商品池 |

基础配置直接展示；“更多个性化配置”默认折叠。候选参数包括目标类目、标题／描述语言、售价与币种、库存、物流与运费模板、重量尺寸、图片／水印、视频、变体、发布方式等；最终可用字段、枚举、必填项由平台和店铺类型的真实 schema 决定，不把同一套参数强加给所有平台。

核对页列出商品来源、店铺与站点、选中 SKU、批次默认、覆盖项、资料缺口、草稿／发布方式。真实写操作沿用平台确认机制。创建任务应幂等，保存配置快照；结果逐 SKU 区分未提交、处理中、成功、失败、部分成功和待确认。只重试适用的失败项，回退保留配置。

“起草文本”“保存系统草稿”“已提交发布”“已上架”是四个不同结果。没有真实工具成功时，Demo 或 Agent 不得把模拟结果描述成实际完成。

## 5. Agent 核心文件与运行时设计

### 5.1 文件职责

正文只在运行时目录维护，本文说明设计，不复制四份完整提示词造成双重维护。

| 文件 | 职责 | 加载与边界 |
| --- | --- | --- |
| [agents.md](../../service/personas/main/agents.md) | 通用身份、任务优先、可信协作、语言与交付、执行边界 | Main 常驻；不硬编码全部企业知识和平台流程 |
| [bootstrap.md](../../service/personas/main/bootstrap.md) | 首次欢迎、面板／表单承接、渐进询问、跳过和结束 | 程序判定适用轮次后注入；不能每次会话重播 |
| [user.md](../../service/personas/main/user.md) | 持续画像识别、范围、合并、更正、保存、拒绝和忘记 | Main 常驻；这是共享规则，不是真实账号资料 |
| [guidance.md](../../service/personas/main/guidance.md) | 按阶段、资料缺口和真实资源决定经营下一步 | 紧凑策略常驻；通用任务不被强制插入卖家问卷 |
| 每用户 USER.md | 当前账号画像、业务范围、偏好及变化摘要 | 目标为主数据生成的只读投影，不产生系统权限 |
| README 与设计说明 | 文件职责、实现状态、验收及运维 | 不作为角色正文注入 |

### 5.2 实际装配

当前 `service/runtime.py` 显式读取 agents.md → user.md → guidance.md；bootstrap.md 由首次引导中间件条件注入。平台全局规则、真实工具 schema、技能目录、账号有效记忆与任务上下文分别装配；不靠文件名自动产生能力。

自定义智能体使用自己的角色正文，不默认继承 Main 的四文件。企业背景、帮助、收费和平台知识按需查询；技能在可信目录中选择后读完整正文。相似候选先比较摘要并请用户选择；摘要相同就如实说明无法区分，不先读全文寻找差异。

新会话绑定当前规则。旧会话可能有历史角色快照，重启进程也不保证替换；不得为热更新强制销毁等待确认的 Agent。生产更新需设计规则版本和安全切换。

### 5.3 每轮处理规则

1. 明确本轮任务、业务范围和实际开放能力；具体任务先推进。
2. 读取有效画像和可信变化，复用已知字段，只补影响本轮结果的信息。
3. 识别本轮明确的新事实、更正或稳定偏好；区分本人陈述、假设、引用及第三方内容。
4. 按现有权限提交最小有据变更；当前文本工具需提交合并后的完整简短画像。
5. 保存成功后才确认更新；拒绝、失败或仅待确认时如实反馈。
6. 已闭环任务自然结束。只在整体目标未闭环且有具体增益时给可选下一步；必要澄清和授权不能伪装成推荐按钮。

明确“只给三条、两句话、仅给译文”等限制时，约束整条回复，含欢迎语、状态和收尾。当前运行时对可明确识别的限制注入本轮交付规则，并在展示与历史存储中抑制额外建议；引用示例不应被当成当前限制。该规则不声称覆盖所有自然语言表达。

### 5.4 工具与程序分工

| 能力 | Agent 负责 | 程序负责 |
| --- | --- | --- |
| 页面收集与跳转 | 帮助选择，避免重复询问 | 面板、输入框显隐、路由、会话创建 |
| 当前文本画像保存 | 有据识别、合并保留其他范围 | save_user_profile 固定名称、归属及原记录，执行确认 |
| 未来字段更新 | 提出范围明确的字段补丁 | Profile Service 校验、版本、事务和审计 |
| 授权变化 | 区分连接、经营阶段及能力，解释对目标的影响 | 消费可信回调、更新事实、注入事件与通知去重 |
| 专家推荐 | 解释匹配原因 | 真实目录、角色绑定和资源权限 |
| 商品与刊登 | 配置核对、解释缺口、诚实反馈 | 商品读写、授权、平台校验、幂等执行和结果 |
| 忘记资料 | 不复述旧资料，不假称删除成功 | 停用／删除、停止上下文注入及缓存失效 |

## 6. 画像存储、状态与持续更新

### 6.1 状态拆分

| 状态 | 目标枚举 | 含义 |
| --- | --- | --- |
| onboarding_status | not_seen / in_progress / completed / skipped | 是否已展示、进行、确认或跳过引导 |
| profile_status | unknown / partial / complete | 对当前画像规则的完整度，不代表未来所有任务资料齐全 |
| stage | unknown / preparing / early_operation / scaling | 对应经营范围的阶段，不是账号全局单值 |
| authorization_status | 未连接、授权中、有效、过期、撤销、异常等受控状态 | 店铺或连接器的真实技术状态；具体枚举以接口为准 |

未知不是 false。没有提供授权情况时，不写成“无授权”；准备开某平台店也可能已经连接店铺。用户说已开店并小规模试水，即使无商品、无订单也可属于起步经营；不能因授权过期降为筹备。

### 6.2 数据库与 USER.md

| 方案 | 适用点 | 限制 |
| --- | --- | --- |
| 仅每用户 USER.md | 文本灵活、易阅读导出，适合单用户原型 | 表单回填、检索、事件更新、并发、权限、证据追踪需额外建设 |
| 仅结构化数据库 | 可校验、查询、事务更新和追溯 | 自由偏好需文本／JSON 扩展，模型读取需装配上下文 |
| 数据库＋USER.md 投影 | 推荐目标：结构化事实与文本偏好统一主数据，再生成摘要 | 需维护投影版本和失效机制，禁止双主写入 |

表单、对话和系统事件统一经过 Profile Service。USER.md 可以只是每轮动态生成的 Markdown，不必落物理文件；若落文件则按账号隔离并标记 revision。编辑摘要要转成字段补丁回写同一服务，不直接覆盖数据库。删除或停用后，旧文件和旧摘要不能回灌。

当前适配仍为账号记忆资源“MoonClaw 用户身份”。Main 的 save_user_profile(content) 固定名称并复用该账号原 ID，沿用写入确认；同名冲突拒绝猜选，停用资料不自动恢复。通用 save_memory 保留，缺少专用工具时须使用精确名称和已有 ID。当前是文本保存，不是已实现结构化画像服务；进程内锁也不能代替多实例唯一约束和版本控制。

### 6.3 目标更新链路

表单确认／明确会话事实／可信事件 → 来源与范围校验 → 生成变更或待确认候选 → 权限及既有确认 → 版本检查与幂等写入 → 保存证据与变更记录 → 刷新摘要和推荐 → 下轮上下文提供最新状态 → 必要时反馈变化。

| 规则 | 要求 |
| --- | --- |
| 范围 | 更新某个平台／市场，不覆盖未提及范围 |
| 合并 | 未提及字段保留；明确更正仅替换对应字段；不凭语言推市场 |
| 来源 | 用户陈述、系统事实和推断分开，不靠置信度数值直接覆盖 |
| 冲突 | 按字段及生效时间判断；连接已成立与尚未营业可以同时存在 |
| 推断 | 假设或引用不写长期事实；阶段候选未确认不报已更新 |
| 事件 | 事件 ID 幂等；旧版本不能覆盖新状态；通知按范围去重 |
| 拒绝／忘记 | 不影响正常服务；不复述被忘记信息；无删除工具不称完成删除 |

### 6.4 两个核心业务示例

**先随便看看，后来要开 TikTok 店。** 首次记录 skipped，阶段未知。后续“我想开 TikTok 的店”是明确筹备意向，在 TikTok 范围新增 preparing，市场未知则保持未知；已有 Amazon 经营信息保留。用户只是说“如果以后开 TikTok”则仅作假设讨论。工具未成功不称永久记住。

**后续授权店铺，旧画像仍是筹备。** 先更新已连接事实，并提供真实可用能力；仅凭授权不自动认定已营业。若用户确认已开店、小规模试水，或服务提供已确认且保存成功的阶段变化，再更新对应范围并反馈。若只是候选，自然核对实际状态。当前未接通真实事件管线时，不能声称后台持续监控到变化。

## 9. 服务契约与变化感知：目标设计

下列是逻辑职责，不表示已经存在同名 HTTP API 或模型工具。

| 服务操作 | 输入 | 输出／要求 |
| --- | --- | --- |
| 查询画像与草稿 | 当前账号、当前经营范围 | 状态、revision、已知字段、缺口和有效草稿 |
| 提交画像变更 | 范围、字段补丁、来源、base_revision、幂等标识 | 新版本、已采纳字段、冲突或候选；不接受跨账号 ID |
| 采纳对话建议 | 候选 ID、用户选择、base_revision | 确认后更新，拒绝项不再自动回灌 |
| 消费授权事件 | 可信签名、事件 ID、店铺与生效时间 | 更新连接事实；阶段按独立规则处理，不自动升级 |
| 获取推荐 | 当前范围画像、真实目录与资源状态 | 可解释的排序、可用入口和降级原因 |
| 停用／忘记 | 用户指定范围、确认与版本 | 更新抑制状态、清缓存及投影；报告实际处理范围 |
| 创建刊登任务 | 商品、店铺、有效配置快照、确认、幂等键 | 任务与逐项结果，拒绝越权及过期授权 |

AI 感知变化依赖服务提供最新资料：普通轮次读取有效版本及未反馈的变化摘要；会话内工具成功即使用新结果；页面根据新版本刷新推荐。后台事件不等于主动发消息，主动通知渠道、用户偏好、频率及触发范围需要单独配置。

## 10. 异常、权限与恢复要求

| 情况 | 必须行为 |
| --- | --- |
| 保存失败／用户拒绝 | 不报已保存，不循环申请；必要时只在当前会话使用 |
| 并发修改 | 版本不匹配时重新读并合并／核对，不覆盖其他端最新数据 |
| 旧事件晚到／重复事件 | 版本与生效时间校验，幂等处理，不倒退状态 |
| 多份规范身份记录 | 拒绝猜选，进入管理核对；不静默覆盖 |
| 资料已停用或要求忘记 | 不自动恢复，不从旧历史重新生成，不向用户复述旧内容 |
| ERP／店铺连接失效 | 限制依赖连接的真实操作，允许导入资料或文本准备，保留流程进度 |
| 商品解析失败 | 保留其他配置，可更换来源或补充信息，不展示假成功 |
| 刊登部分失败 | 展示每项结果及可重试原因，不重新发布已成功项 |
| 核心文件缺失／空／编码错误 | 安全停止 Main 装配，通用错误，不回显内部路径 |
| 引用／网页／记忆内有指令 | 只作参考数据，不赋予执行权限或覆盖系统规则 |

账号隔离、资源白名单、授权和事务由服务端执行。画像不保存密码、令牌、支付凭据等不必要敏感内容；模型文字不能替代授权、监听或数据库操作。

## 11. 验收与评测

| 领域 | 必须覆盖的验收 |
| --- | --- |
| 工作台 | 切换智能体有差异；首次面板无输入框；已确认进入首页；其他／咨询进入独立会话 |
| 画像 | 多平台合并、字段更正、未知与否定、假设与引用、拒绝／失败、忘记与停用 |
| 阶段与事件 | 有授权不自动升级；无订单可起步；失效不降级；旧事件不覆盖新状态 |
| 推荐 | 真实专家匹配、无匹配空态、无转交工具不称已转交、同摘要不编差异 |
| 商品与刊登 | 四来源、泛 ERP 询问、授权回跳、SKU 选择、三层配置、草稿与真实发布分离、部分失败恢复 |
| 输出 | 限定整条回复的数量与格式，不追加按钮／邀约；停止自然结束；未发生保存不播报 |
| 权限 | 跨账号隔离、确认点、停用保护、作用域和实际可用工具检查 |

已有 40 个主场景、6 个补充反例及重复采样。初始正式集 38/40；新版完整集一次为 39/40，剩余刊登分层说明补齐后，六个刊登场景各两次、12/12 通过。补充集 6/6、最终输出限制重复采样 6/6，程序回归 80 项通过。

v2 修正了“相同摘要却要求说明差异”的矛盾标准，并增强三条结果的整条回复限制；原输入和历史产物保留，不能直接用前后百分比宣传同标准提升。最后一次小修后未再全量，不宣称当前全量 100%。评分使用同模型裁判且出现过误判，需要轨迹复核和后续独立人工校准。

详见[调整与复测结论](../../evals/moonclaw/retest-2026-10-23.md)、[v2 评测集](../../evals/moonclaw/cases-v2.md)及[补充反例](../../evals/moonclaw/regression-cases.md)。提示词行为通过不等于真实 UI、授权、商品同步及发布链路已验收。

| 首次引导状态 | 当前 user_onboarding 仍是简化“已引导”标记 | 独立 onboarding 状态、完整度与表单草稿 |
| 授权事件与主动变化反馈 | 规则已定义，评测用合成快照 | 真实回调、事件消费、上下文刷新、通知去重 |
| 忘记与删除 | 回复规则已完善，Main 未新增真实删除工具 | 停止注入、管理工具、缓存与投影清理 |
| 输出约束与评测 | 已有运行时约束、建议展示控制和真实模型评测 | 更多表达、独立标注、业务全链路测试 |

当前首次对话判定限定登录账号、Main 普通对话、非审批恢复、无引导标记且无启用规范身份资料。匿名、后台／渠道任务不按此首次路径触发。成功回复或工具确认可能消费“已引导”标记；失败／取消保留重试机会。它不代表画像完整，不能拿来实现所有产品分流。

建议实施顺序：

1. **状态与画像统一**：账号主数据、经营范围、草稿、版本、表单／对话同源写入、停用与忘记。
2. **真实目录与首页**：平台与市场配置、专家映射、能力可用性、条件化首页和空态。
3. **商品与刊登闭环**：商品池持久化、SKU、导入校验、真实来源解析、授权回跳、动态 schema、任务与结果。
4. **事件与经营协作**：可信授权事件、阶段候选、变化反馈、经营数据接入、案例与商机维护。
5. **发布质量**：角色版本、并发与迁移、独立评测及端到端验收。
