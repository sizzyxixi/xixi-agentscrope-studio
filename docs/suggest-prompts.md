# 会话下一步建议

所有工作空间智能体通过 `BootstrapMiddleware` 统一接收下一步建议协议，包括自定义智能体。无需为每个智能体分别修改人设，也不需要额外请求模型生成建议。

## 是否引导的规则

**默认不引导。** 先完成用户本轮请求，再判断下一步是否能帮助推进尚未完成的目标。优先级：用户明确的停止/格式要求 → 不引导场景 → 可引导场景及质量条件。仅仅存在可聊的话题不构成引导理由。

| 场景 | 是否引导 | 示例或处理 |
| --- | --- | --- |
| 复杂任务已完成一个阶段，整体目标尚未闭环 | 可以 | 用户目标是安装/接入，当前只完成脚本分析，可提供“审查脚本安全风险”或“整理安装步骤” |
| 开放探索/方案比较，需要可选深入方向 | 可以 | 已比较方案，可选择其中一个方向继续制定实施计划 |
| 用户主动问“接下来可以做什么” | 可以 | 提供少量可直接发送、符合当前上下文的请求；要求纯文本清单时只交付正文 |
| 问候、致谢、收到、满意、停止、取消、拒绝继续 | 不需要 | 自然结束，不加按钮或“还有什么可以帮你” |
| 简单事实、术语解释、状态查询 | 不需要 | 直接回答，例如“当前模型是什么” |
| 完成翻译、计算、改写等明确请求 | 不需要 | 交付结果即结束，不额外推销其他操作 |
| 最终交付，目标已经闭环 | 不需要 | 已修复并完成用户要求的检查，不再建议“检查修复” |
| 必须补信息/澄清、选择相似技能 | 不使用此组件 | 在正文明确询问，等待用户回答 |
| 权限授权、写操作/定时任务确认 | 不使用此组件 | 使用专用确认组件，点击建议不能充当授权 |
| 进度、执行中、失败/拒绝、响应中断 | 不需要 | 说明现状、错误或必要修复条件，避免制造新任务 |

建议通常 **1–2条**，确有多个不同方向时最多4条；必须具体、可继续、有信息增益、互不重复。不得将用户本轮已经要求完成的步骤推迟成下一步，不重复已完成内容，不假定未提供的数据或平台没有的能力。不要提供“继续”“了解更多”等泛化按钮。用户使用一次建议后，不机械地生成下一组。

不自行扩大用户目标：用户只要求方案、分析或文档，交付完成就算闭环，不能仅因“后面还可以实施”继续推送建议。

这部分语义判断由全局提示词负责，避免用关键词正则判断复杂意图，也不增加一次模型请求。后端额外强制过滤未完成、无正文、存在失败/未完成工具调用或未批准确认点的回复。必要的纠错、澄清始终留在正文。

## 展示和数据协议

模型在需要可选引导时，在回答末尾独立输出：

```xml
<suggest_prompts>[{"prompt":"请整理安装步骤。"},{"prompt":"请审查脚本安全风险。"}]</suggest_prompts>
```

数组每项只有 `prompt`。后端验证、去重后最多保留 4 项，每项最多 500 字符；格式异常、无正文、未完成、中断或工具受阻的建议不作为可点击操作。代码块中的协议示例保持正文展示。

后端从回答正文分离建议，保存到现有消息 `parts_json`：

```json
{"type":"data","name":"suggest_prompts","data":[{"prompt":"请整理安装步骤。"}]}
```

最终 `message_parts` SSE 同时携带清理后的 `content` 和结构化 `parts`。会话刷新后仍从原消息读取，无需数据库迁移。前端在流式过程中隐藏协议及跨分片的未完整标记，回答完成后展示 HeroUI 按钮。

按钮直接显示完整 `prompt`，点击填入当前会话输入框并聚焦，不自动发送。仅最新回答在会话空闲且正常完成时展示按钮。用户继续对话后，历史建议保留在消息数据中但不再占用页面空间；流式响应或等待确认期间也不展示。必需的技能选择、执行授权和权限确认不使用此组件，点击建议不构成执行授权。

语言跟随当前对话，由模型生成；组件的无障碍标题使用全局中英文词典。
