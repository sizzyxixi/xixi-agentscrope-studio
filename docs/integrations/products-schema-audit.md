# 商品库与 products 表字段核对

基准：2026-11-13 用户提供的 `products`、`products_sku` DDL。本次不新增、删除或修改数据库列，不修改 `attributes`、`variables`、`extend` 的内部结构。当前页面仍使用本地工作区，以下字段处理不代表已接通数据库 CRUD。

## 已移除的无依据 SPU 字段

| 原实现 | 问题 | 调整 |
| --- | --- | --- |
| 独立核心卖点 `selling` | 表中没有该列；不能与 `efficacy` 视为两个可分别维护的业务字段 | 移除当前商品库独立表单和详情项，功效单独对应 `efficacy` |
| 包装说明 `packaging` | SPU 表中无该列 | 移除表单与详情；不混入 `extend` 或 `attributes` |
| SPU 产品尺寸 `dimensions` | SPU 表中无该列 | 移除 SPU 编辑项；SKU 尺寸不再从 SPU 默认补值 |
| SPU 价格币种 `currency` | SPU 表中无价格或币种列 | 移除 SPU 编辑和商品库导出的币种项；不再作为店铺草稿的默认币种 |
| 材质与外观、工艺细节、营销卖点 | 当前 SKU 详情包含自行扩展的创作描述，未有相应表结构依据 | 从当前 SKU 详情去除这些额外描述项；按 products_sku 表保留货号、规格、图片、价格、重量、尺寸等基础信息 |

## 已纠正的映射

| 已有列 | 原问题 | 当前处理 |
| --- | --- | --- |
| `title` / `cn_title` | 标题只有一份 `name`，中英未区分 | 分别编辑、展示、导出；展示标题优先中文、其次英文；中文清空不覆盖英文 |
| `description` / `cn_description` | 中文描述存在 `erp.description`，英文缺失；刊登草稿可能用卖点顶替描述 | 分开维护中英文描述；不以卖点或功效代填描述 |
| `ingredient` / `efficacy` | 材质与成分混名，功效与卖点混用 | 归入类目属性，均为选填；详情只展示已填写值，编辑按需添加／移除，导入不因缺失而失败；通用历史材质／营销文案不自动重命名为这两列 |
| `spu_code` | 仅有前端 `code` | SPU 编码对应现有列；编辑与导出使用统一映射 |
| `brand_name` / `category_name` | 只维护视图别名 | 对应现有名称列；不根据名称臆造品牌 ID、类目 ID |
| `target_user` / `keyword` | 目标人群是视图字段，关键字未呈现 | 使用现有列维护；不新增字段 |
| `source_type` / `supply_source` | 采集方式、采集来源和货源混用 | 两者分别展示，按已知业务值转成中文；不将“Excel 导入／识图／手动”直接写成已授权的采集来源 |
| `source_url` / `remarks` | 只存在前端嵌套字段 | 显式映射现有列，保留旧工作区兼容读取 |
| `main_image` | 封面只从素材关联计算 | SPU 封面优先读取已有主图列，再兼容旧素材关联 |
| `last_gathered_at` / `last_gather_batch_no` | 时间混用首次采集或编辑时间 | 成功采集、重采或追加 SKU 时更新最近采集时间和对应批次；编辑 SPU 不伪造采集时间 |

`app/product-fields.ts` 中的 `productUpdatePatch` 只输出本次可编辑的既有 SPU 列。账号归属、状态、JSON、主图和关联数据不由文本表单随意覆盖。历史本地视图别名保留兼容，避免破坏历史创作快照；它们不是新增的数据库字段。

## 不能仅凭这张表确定的实现缺口

1. **SKU 字段已核对**：价格、重量、重量单位、产品及包装长宽高均有对应列，保留展示。删除独立 SKU 名称、颜色、外观、工艺、营销卖点。`price` 的注释仍只有“价格”，页面和新 Excel 模板统一叫“价格”，旧模板的“售价”表头兼容读取，不自行定义为成本或售价。
2. **规格 JSON 不解释或改写**：按用户补充要求，本次只关注字段展示。`spec` 继续展示规格文本，`variables`／`variants` 原值保留；SPU 的销售规格可展开只读原始 JSON，不新增独立颜色列、不改 JSON 结构、不新增规格编辑流程。
3. **认领关系信息不足**：`claim_status` 只能表达未认领／已认领，仍无法承载目标店铺和站点关系；SKU 表虽有自己的 claim_status，也不代表已保存多店铺关系。既有认领功能暂保留在本地工作流，需由实际认领关系接口／表承接，不能扩展 `products` 来凑字段。
4. **刊登草稿另属实体**：文案语言、店铺刊登价、币种、素材选择和导出记录不是这张 SPU 表的字段。保留既有流程，不将其写入 SPU 更新 patch；需核对实际刊登草稿存储。
5. **`status` 枚举未提供**：当前“资料准备”是前端检查结果，不能当成数据库 `status`，也不能把状态数字自行映射成采集失败／待刊登。
6. **素材关联模型未提供**：`main_image`、`images`、`video` 与素材库文件、场景和 SKU 范围的同步规则尚未确定，需实际图片／视频字段格式和关联接口。不得把所有图片强制只存为一个主图字段。
7. **删除与归档**：`deleted_at` 表示软删除时间。当前本地删除、独立归档状态不能被当成真实后端软删除／恢复流程；归档也不能随意占用未知的 `status` 枚举。
8. **来源范围**：现有采集界面支持 Amazon，但本次给出的 `source_type` 注释没有说明 Amazon 的值；Excel、识图的实际来源取值也需要接口确认，不根据输入方式推断来源。
9. **账号隔离与系统字段**：`customer_id`、`customer_uid`、`products_id`、各类 ID 及系统时间需由后端提供并校验，前端不根据公司名称或用户输入伪造这些值。

## 验证

新增用例覆盖：双语独立保存、空值不复活历史字段、无依据 SPU 字段不进入更新 patch、JSON 与超大 ID 保留、采集时间不使用更新时间。采集回归覆盖最近时间与成功批次同步；既有 SKU、认领、素材和导出用例继续执行。

## SKU 字段展示调整

| 已有列 | 页面展示与处理 |
| --- | --- |
| `sku_code` / `source_sku_code` | 分别显示 SKU 货号与来源原始货号，不混成同一个货号 |
| `spec` | 规格文本；不再叠加一个自行维护的颜色字段 |
| `price` | 保留“价格”，0 值正常显示；不自动当作店铺刊登价 |
| `weight` / `weight_unit` / `weight_class` | 展示重量及单位，优先新单位、兼容历史单位；空的新行按 g；不暗中换算重量 |
| `size` | 保留原始尺寸说明，与实测长宽高分开展示 |
| `product_length` / `product_width` / `product_height` | 三个数值编辑项，详情汇总为长 × 宽 × 高（cm） |
| `package_length` / `package_width` / `package_height` | 三个包装尺寸编辑项，详情汇总展示 |
| `spec_id` / `batch_no` | 来源规格 ID、采集批次只读展示 |
| `claim_status` | 已有 1／2 值显示未认领／已认领；未提供则不猜测数据库状态 |
| `images` | 可用 SKU 图片可作缩略图，仍保留原始字段表示 |

SKU 更新字段只允许现有可编辑列；不写独立名称、颜色、外观、工艺、卖点，也不改用户、SPU 关联 ID 或规格下标。SQL BIGINT 标识按字符串保留。历史尺寸字符串只用于兼容展示，实际长宽高使用已有六个字段，显式空值不会被旧尺寸文字覆盖。

刊登草稿继续独立于来源商品数据：来源 `price` 不自动成为刊登价；导出保留来源价格，店铺价格与币种单独标记。价格、货号、SKU 规格、尺寸相关显示已同步到列表、详情、编辑、素材关联选择和导出。

## 基础资料分区与 38 列展示复核（2026-11-16）

复核依据为本轮用户再次提供的 products DDL，共 38 列。原基础资料只覆盖 17 列，其余 21 列此前没有查看位置；本次不扩展编辑权限、不改表，通过补充只读信息与可展开区域覆盖全部 38 列。

| 区域 | 原来缺少的字段 | 现在的处理 |
| --- | --- | --- |
| 基础信息 | `products_id`、`brand_id`、`category_id` | 隐藏自增主键 `id`，仅展示产品 ID（`products_id`），品牌和类目 ID 隐藏，仅展示名称；中英文标题合成一组，中英文描述合成一组 |
| 类目属性／销售规格 | `attributes`、`variables` | 原始 JSON 只读展开，不解析或编造属性、规格层级 |
| 运营信息 | `status`、`claim_status`、`ai_choose` | 状态只读；产品状态未知枚举保留数字原值，认领按 1／2、AI 选品按 0／1 显示已定义含义 |
| 来源与采集 | `operate_platform`、`source_product_id`、`detail_synced_at`、`last_gather_batch_no`、`extend` | 补充操作平台、来源标识、详情时间、成功批次与只读扩展 JSON，保留独立的最近成功采集时间 |
| 原始媒体 | `main_image`、`images`、`video` | 可展开查看原始字段，链接可打开；不把素材库关联数量当作这些字段已有值 |
| 系统记录 | `customer_id`、`customer_uid`、`created_at`、`updated_at`、`deleted_at` | 可展开只读，保持归属、记录时间和删除信息原值 |

`productInformationSections` 是详情和编辑只读信息的共同来源；双语标题、描述使用同一对照布局。原有 13 个文本编辑字段白名单不变，JSON、来源标识、状态及系统字段均不写入文本更新 patch。空值不通过推断补齐，0 和 BIGINT 字符串标识保持精度；本地认领工作流不反推数据库认领状态。新增测试逐项核对 38 列覆盖、双语独立、未知状态、原始 JSON 不变及时间区分。

## SKU 档案 29 列复核（2026-11-16）

取消折叠面板内独立的重量／价格／产品尺寸摘要卡，这些信息并入普通字段区，保留原有的 SKU 折叠交互。空值统一显示 —；展开头部的价格和规格也不再显示待补充标签。

| 字段 | 核对及处理 |
| --- | --- |
| `weight`、`weight_unit`、`price`、产品和包装六项尺寸 | 合并进普通字段区；重量与单位独立展示，0 价格不被隐藏，部分尺寸不被旧文本补齐 |
| `sku_id`、`collect_status` | 原来没有查看位置，本次补到常用字段；西之月 SKU ID 与本地记录 ID 分开，采集状态只映射已有成功值 2 |
| `id`、`pid`、`products_id`、`customer_id`、`customer_uid` | 补到可展开的来源与系统记录，全部只读，不用父商品 ID 代填缺失关联 ID |
| `weight_class`、`created_at`、`updated_at`、`deleted_at` | 原始历史单位及系统时间只读，不执行静默单位换算 |
| `variants`、`images` | 原始 JSON 只读，不定义新的规格结构；图片字段的 image_name／url 格式可正确提供缩略图，原数据保持不变 |
| `sku_code`、`source_sku_code`、`spec`、`size`、`spec_id`、`batch_no`、`claim_status` | 保留原字段含义；批次号显式为空时不恢复历史别名，未知状态原样显示 |

`skuArchiveFields` 统一生成常用字段和追溯字段，覆盖 products_sku 的全部 29 列，每列仅归属一个展示位置。编辑白名单不变，不新增名称、颜色、币种或其他表外字段。新增验证覆盖全量字段、0 值和 BIGINT、单位、部分尺寸、未知状态、原始 JSON 不变及命名图片缩略图。

## 商品列表与页内编辑（2026-11-17）

移除 SKU 名称及重复编号列，SKU 首列仅显示图片与 `sku_code`。SPU 操作为编辑／全部认领／删除，SKU 操作为编辑／认领／删除／认领记录，均为文本按钮。编辑／查看使用相同资料页，保存、取消在当前页面完成；新建复用资料页，不再使用独立编辑弹窗。认领记录按当前 SKU 的实际范围过滤，`sku_id` 缺失显示 —，草稿关联只链接已有刊登任务中的资料，不虚构关系表字段。SKU 删除保留 SPU 和其他 SKU，并清理对应的范围关系，共用文件保留。

## 商品资料布局归并（2026-11-17）

当前查看和编辑仅保留「基础信息」「来源信息」两个常显分区；原类目属性与运营字段并入基础信息，源 JSON、媒体原值和系统记录合并到「更多资料」中默认折叠。35 个可展示字段保持原有映射，不删除数据或改写 JSON；内部主键、品牌 ID、类目 ID 仍隐藏。短字段使用紧凑多列布局，标签和值同行；中英文标题和描述继续成对展示，成分／功效仍为选填且可按需添加。
