# ERP 商品采集前端适配

范围：商品库中的链接采集、Excel 导入和识图采集交互。需求基准为 ERP《商品采集箱优化 PRD》及 v2.2 Excel 模板。未实现采集器、AI 或 OSS 后端。按最新交互要求，当前 Excel 和识图弹窗均仅展示前端流程，不调用 ERP 入库，也不写入商品库；Excel 使用固定示例数据，不解析上传文件；下文真实采集及校验契约作为后续接入依据保留。

识图当前流程：图片仅在浏览器校验格式、大小并压缩预览，不调用 `upload`／`analyze`／`prepare`，不记录正式采集成功或失败任务。“开始分析”始终可直接体验（图片处理中暂不可点）；未选图片时使用本地参考图。第二步用约 4 秒递增进度展示读取图片、提取信息、整理资料，再进入固定资料的人工确认。确认仅更新弹窗状态，不调用 `commitCollection`，关闭弹窗只隐藏界面，图片、进度与确认资料保留在商品库页面的任务状态中，后台继续分析；再次打开恢复当前进度，后台已完成则直接显示确认页。各步骤的“取消”会终止任务、清空资料并释放图片 URL，完成后清理本次任务；离开商品库页面时也清理资源。不提供跳过 AI 的入口，也不显示采集服务不可用。以下图片上传和分析契约为后续真实服务接入保留。

`app/collection-service.ts` 定义 `CollectionAdapter`。在客户端初始化时调用 `configureCollectionAdapter(adapter)` 注入 ERP SDK 或应用已有 API 客户端。没有臆造 ERP 路由；默认适配器明确返回 SERVICE_UNAVAILABLE。格式正确的链接仅进入任务队列，不生成商品，不返回伪造 AI 结果或 OSS 地址。

- `authorization(source)`：只返回 authorized / expired / unavailable。界面不接收和展示公司账号凭据。
- `collect(request)`：ERP 完成抓取、字段映射和图片转存后，返回完整的 `ExcelProduct`。`requestId` 是批次与输入序号组成的稳定幂等键，刷新页面恢复未完成任务时保持不变。ERP 负责后台任务、并发限流和长时间队列；此方法可封装提交/轮询，直到最终成功或抛出标准原因码。
- `upload(file, {batch, role})`：浏览器压缩长边至 1600px 后上传，返回 HTTPS oss.westmonth.com 地址。role 为 main / size_chart / ingredient / other；辅助图按批次留痕，不进入商品素材集。
- `analyze(images, {batch, signal})`：一次传入主图与已上传辅助图，封装 ERP 的 POST /ai/gather/product/analyze。尊重取消信号。字段键见 `use-image-import-task.ts` 的 fieldKeys，和模板 20 列一一对应。每项返回 value、source、confidence、exact；source 为 ocr / visual_estimate / category_ref / none。推断数值只能返回范围，不能返回伪精确数值。业务提示支持 NOT_PRODUCT / MULTIPLE_SUBJECTS / LOW_QUALITY。前端等待上限15秒；超时或分析失败返回图片步骤，支持重试或调整图片。AI 分析成功后才进入人工确认，不提供跳过分析的入口。
- `prepare(items, {batch})`：校验图片可访问性、转存图片并保存已确认商品。返回已完成的商品，保留父商品编码、SKU 货号及一一对应的图片关系；不会返回“部分字段已完成”的商品。Excel 在调用前已按 SKU 判重，每组商品独立处理，失败不影响其他组。ERP 须再做相同判重及请求幂等保证，防止多端并发重复。

链接请求在工作区 Provider 执行，关闭弹窗、切换页面不停止，任务与商品一起按账号写入原有 IndexedDB。刷新后会用稳定 requestId 重试未完成请求。浏览器关闭期间的执行和跨设备同步依赖 ERP 后台，当前前端不替代服务端队列。

最终成功需通过 assertComplete：必填商品信息、SKU 规格、重量与六项尺寸、单位，以及主图和SKU图转存均完成。失败不写商品或 SKU。TIMEOUT / RATE_LIMIT / IMG_FAIL / NETWORK_ERROR / SERVER_ERROR 自动退避重试一次；格式、权限和授权错误不自动重试。若 ERP 已执行重试，应在适配器中统一重试职责，避免双重重试。

链接重采按来源类型 + 来源商品标识 + 站点定位 SPU、再按 SKU 货号替换来源事实，保留商品与 SKU ID、人工关联素材、创作说明和渠道内容快照。被替换的来源素材只解除旧引用，文件不删除。Excel 按显式SKU货号，或显式父编码+规格判重；两编码都留空不做跨批次判重。新增 SKU 追加到原商品，不覆盖已有商品级编辑。

Excel 下载为两个工作表：商品导入模板_v2.2、填写说明；前六行为表头/说明/示例，正式数据从第七行开始。CSV和错误明细工作簿为表头后直接跟数据。错误导出保留原始20列，可修正后重传。前端支持 XLSX / XLS / CSV，最多2000行、20MB。

Excel 交互采用「上传 → 校验 → 落库 → 完成」四步。上传区使用居中单列布局，将文件类型、行数及大小限制合并展示；下载模板和选择文件并排，弹窗内不再展示模板填写说明。选择或拖入文件后，只读取文件名称，立即进入校验步骤，显示约1.5秒「校验中」后展示 `product-import-demo.ts` 的固定6行结果，包含可导入、重复、提示及错误。重新上传会重置校验状态，所选文件内容不影响结果。

校验页保留文件名、总行数及商品组数，使用一张分页表合并结果；筛选仅影响展示。校验表仅显示必要的摘要列，不提供展开全部字段的入口；导出的错误明细来自固定数据，不是上传文件。存在错误时须勾选「仅导入通过行」才能继续。确认后通过本地进度进入完成步骤，不调用 `prepare`／`assertComplete`／`commitCollection`，不新增真实商品或采集任务。完成页保留结果摘要及「导出失败明细」按钮，不展示未入库明细表。

Excel 弹窗左侧提供状态切换面板，只显示当前步骤对应的按钮：上传为初始化／成功／校验失败，校验为全部通过／无数据／全部失败／部分通过，落库及完成页为全部成功／部分成功／全部失败。初始化回到空白上传区并清空文件及结果；其他预设直接展示对应结果，不要求先选文件；切换时取消旧定时器并重置确认状态。无数据及全部校验失败不可确认导入，全部落库成功不显示失败导出入口，部分成功／全部失败导出的行数与当前失败数一致。面板与内容区位于同一弹窗交互范围；点击内容、状态按钮或遮罩不会关闭 Excel 弹窗，关闭、取消及完成按钮正常退出。

优化后的下载模板位于 `public/templates/product-import-v2.2.xlsx`，保留两个工作表及版本兼容布局。商品级与SKU级表头分色，12项必填使用星号，说明压缩到第2行，保留第3—6行示例；第7行为空白输入区，不写入可能被误导入的占位文本。冻结表头与识别列，重量单位提供 g/kg 下拉。填写说明集中列出分组、判重、数值、图片、部分导入及错误修正规则，并提供20列字段速查。模板价格沿用已确认的中性“价格”口径，旧文件“售价”表头仍兼容。

真实文件读取、解析及校验工具保留，当前 Excel 弹窗不调用它们。附件中的多URL分隔、重名规格补后缀、空品牌自动填值等描述不代表现有解析器已支持这些规则；正式接入时仍需对齐接口及测试，不通过模板说明启用。

验证：运行 `node --test tests/product-import.test.mjs tests/collection-service.test.mjs tests/product-import-workbook.test.mjs`，再运行项目 TypeScript 与 ESLint 检查。
