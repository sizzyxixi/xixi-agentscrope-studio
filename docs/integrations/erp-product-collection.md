# ERP 商品采集与导入接入契约

## 1. 职责与数据边界

业务规则、20 列模板映射、失败码和验收要求以[商品库管理需求文档](../../../PRD/商品库管理需求文档.md)第 3、12、13 节为准。本契约约束项目适配层与实际 ERP／AI 服务的接入，不将本地状态展示视为真实采集或入库能力。

商品库通过 `CollectionAdapter` 接入来源采集、图片处理与保存，由 `configureCollectionAdapter()` 注入业务客户端。公司来源采集账号在后端维护，用户目标店铺授权属于经营中心刊登，两类授权不可混用。图采依赖 AI 服务 `POST /ai/gather/product/analyze`；该地址为服务契约，不意味着本项目已实现 ERP 接口。

使用既有 `products`、`products_sku` 字段，不新增 `source_site`、`ai_raw`、库存或任务列。SPU 与 SKU 关联必须使用 `products_sku.pid = products.id`，业务编号 `products_id` 不作为关联主键。BIGINT 标识按字符串传递。

## 2. 适配能力

| 能力 | 返回与约束 |
| --- | --- |
| `authorization(source)` | 来源权限由服务端校验，不向界面提供公司凭据，不作为目标店铺授权入口 |
| `collect(request)` | 获取来源商品、SKU 与图片；稳定 requestId 对应同一任务，可封装提交与查询；必要资料、转图及保存未完成时不能返回成功入库结果 |
| `upload(file, context)` | 返回有效的 `oss.westmonth.com` 存储地址；传输角色不定义素材场景，辅助图上传不等于加入商品图集 |
| `analyze(images, context)` | 一次处理完整图片组，返回建议及来源；区分 OCR 精确值、估算范围和未识别值，支持任务取消与恢复 |
| `prepare(items, context)` | 校验图片、权限、重复和字段，按事务边界保存；返回实际成功对象、重复跳过及明确失败范围；承担保存幂等 |

来源成功对象、已保存对象与待确认的 AI 建议必须区分。验收读取实际批次、商品与失败记录，不以固定资料、模拟结果或流程动画代替。

## 3. 写入与追溯

| 数据 | 约束 |
| --- | --- |
| `source_type` | 1688 主动拉取使用 alibaba_lapp；Amazon、Excel、图采分别使用 amazon、excel、image；兼容历史来源值 |
| 来源编号／站点 | offerId／ASIN 写 source_product_id；规范化 source_url 保留站点域名，站点和请求上下文由任务保存，不新增商品列 |
| `spec` | 可读规格统一读取此列，不以 variants 下标拼接作为必经路径 |
| `price` | 链接价格为来源售价或报价，不是成本或店铺最终售价；不推定币种 |
| 图片 JSON | 多图保存 image_name、url，保留现有 mediumtext／text 类型；成功商品不得残留应转存的外部源图地址 |
| 成功状态 | products_sku.collect_status＝2；新建为未认领，重采／追加不重置既有认领；失败与执行中仅在任务／失败对象保存，不向商品表写占位行 |
| 批次与时间 | 沿用 36 位 UUID；成功才更新 last_gathered_at、last_gather_batch_no 及 SKU batch_no，普通编辑只更新 updated_at |

三类采集不生成或覆盖 variables、keyword、video、operate_platform、spec_id 和历史 size 文本；保留原字段、历史值及人工维护能力。不采集库存、发货区域或类目，不覆盖既有人工类目；平台匹配、真实库存及最终定价在经营中心处理。已有 variables 可只读展示，SKU 规格仍以 spec 为准。

## 4. 链接采集与重采

支持 1688 标准商品链接／ID、Amazon 标准商品链接／ASIN。忽略空行，按来源、站点及来源商品标识清洗去重，最多 50 条有效输入，保留原始行号。1688 短链不进入来源调用；Amazon 只采当前子 ASIN，不按整条 Listing 扩展。

1688 通过公司轻应用主动拉取，Amazon 通过目录与价格接口获取。格式、来源不匹配等问题逐项反馈；不提供浏览器插件补采或半成品商品状态。

对同账号、同来源、同站点、同来源商品执行重采，按来源 SKU 身份匹配已有 SKU。链接生成规格按来源维度组合，重复时稳定补后缀；规范化后最多 255 字。不得按标题、业务产品 ID 或规格后缀判断父子身份。

本次来源字段覆盖包含用户对相应字段的修改，应在提交前说明；新 SKU 追加，未返回的旧 SKU 不自动删除。创作文件、素材关系、经营会话与停采历史字段保留。

每个来源输入的资料、全部应保存图片及关联 SKU 形成一个成功单元。任一必要环节失败时不提交本次新增或覆盖，保留原有效数据；重试整条输入，不先保存裂图商品。全部成功仅返回数量，失败返回原输入、行号和原因，不创建失败商品 ID。

## 5. Excel 导入

流程为上传 → 校验 → 落库 → 完成。模板含“商品导入模板_v2.2”和“填写说明”，正式数据从第 7 行开始；CSV 与失败导出为表头后直接跟数据。支持 XLSX／XLS／CSV，最多 2000 行、20MB。模板固定 A～T 共 20 列，准确映射见主需求文档。

同显式父码聚合，商品级资料取组首行，后续行不同值提示但不覆盖首行。空父码逐行生成独立 SPU，相同标题不合并。生成编码在预览与保存间保持稳定。

必填共 10 项：组首行中文标题、主图，逐行规格、重量、产品长宽高与包装长宽高。成分、功效、品牌、描述、货源、价格等选填；重量单位省略按 g。重量与尺寸必须为纯数字、正数，尺寸固定 cm；价格非负且最多 2 位小数，不填英文资料，也不清空存量英文值。

组首行必填错误影响整组，SKU 错误影响对应行；文件内 SKU 货号和组内规格重复标错，不自动加后缀。提示可与通过行重叠，不重复加总。无有效非重复行时不能确认保存。

存量去重顺序：显式 SKU 货号优先；没有显式货号时按显式父码＋规格；两码都生成时不保证跨批次去重。命中只跳过，不覆盖；显式父码命中既有商品的新 SKU 只追加，公共资料保留，历史父码歧义反馈冲突。

商品主图按组、SKU 图按行转存；填写了无效 SKU 图不能当作未填写。Excel 不写 products.images，追加不清空既有图集。每个有效 SKU 与必要父档一并提交，没有成功 SKU 的新组不产生空 SPU。

完成报告实际新增 SPU、成功 SKU、跳过及失败行数，提供失败明细导出，不重复铺开未入库列表。失败文件保留原 20 列、原行号和原因；修正重传不重复保存成功行。

## 6. 图片分析与确认

一组 1 张主图与最多 4 张辅助图，最多 5MB／张，JPG／PNG／WEBP，长边不超过 1600px。不设用途选择或另设主图操作，不反查货源、不调用图搜；一组只生成一个 SPU、一个 SKU。

主图转存失败阻断，辅助图重试仍失败时明确排除后以剩余图片分析。全部可用图片一次传入 images[]，不因每张图片发起一次独立分析而重复生成商品。

AI 结果经用户确认才可保存：OCR 标注可给精确值；视觉估计、类目参考仅给区间，必须人工核实为具体值；没有值则留空。成分只读取可见标签，功效、规格、价格及货源不由视觉模型猜测。必填、数值、图片沿用 Excel 对应规则，成分与功效仍选填。

主图不重复要求 URL 输入，SKU 货号按父码加 -01 生成。辅助图不写产品／SKU 图集，不定义按批次永久保留功能。确认成功后 claim_status＝1，只进入商品库，不自动进入刊登会话。

关闭窗口恢复同一进度或确认结果；明确取消清空任务，后到结果不得入库。没有跳过 AI 手填或从人工确认返回调整图片的分支。分析失败提供重试／取消，非商品或多主体图片重新提供单商品图片后再分析。

按 1、2～3、4～5 张分别配置 20、30、40 秒分析超时，15 秒后提示较慢但仍查原任务。AI 自动重试最多 2 次，关闭重开不重置次数。性能目标按主需求在真实服务下验证，不宣称已经获得供应商 SLA。

业务用量按图片数计，默认 200 张／人／天可配置；公司月基准 30,000 张、80% 告警。同 request_id 恢复、重传不重复记录业务用量；同账号同图片组同配置可复用有效结果，任务服务保存幂等与计量，不借用不存在的 ai_raw 列。供应商实际计费独立核对。

## 7. 任务、失败与执行保障

批次沿用 products_gather_records，失败使用 products_gather_fail 的独立业务对象，包含批次、来源标识、原因码、重试次数、归属与时间。失败无标题、图片或产品 ID；不混入商品列表或刊登选择范围。

LINK_INVALID、PLAT_MISMATCH、NOT_FOUND、AUTH_EXPIRED、NO_PERMISSION 不自动重试；STOCK_UNKNOWN、RATE_LIMIT、TIMEOUT、PARSE_FAIL、IMG_FAIL 最多自动重试 1 次。STOCK_UNKNOWN 为来源必要资料缺失的历史码，不代表采集库存。来源单次调用默认超时 15 秒；AI 的次数与超时独立配置，不能叠加多端重试。

任务队列、令牌桶、指数退避和随机抖动由服务端统一管理。1688 内部阈值默认不超过 8 QPS，Amazon 目录按账号×应用默认不超过 1.8 次／秒，价格接口按实际配额独立限流；配额降低时同步收紧。图片队列初始并发 5、最多配置为 10。

提交数按链接输入／Excel 行／图片组计算，分别核对成功、失败、跳过，告警行不重复加总。关闭或刷新不取消后台任务；明确取消只停止可中止的未执行范围，已成功项保留，不将本地关闭当作后端已取消。

手动重试只执行选中失败项，成功后解除未处理失败并保留轨迹。请求结果未明先查原请求，服务端保存成功但前端未同步时只补读／同步，不重新建档。服务端按账号校验所有请求、商品、图片、缓存与失败记录，统一来源凭据不改变用户数据隔离。
